# 手机转发长图 JSON 结构

使用 `output_policy` 明确选择单版或双版。中性信息整理使用 `single`；针对具体可交易标的且包含投资建议、评级、估值、目标价、仓位或交易判断时使用 `dual`。无法判断时先询问用户。

## Single 单版示例

```json
{
  "output_policy": "single",
  "title": "存储芯片分析师王明：HBM扩产仍追不上需求",
  "subtitle": "三星、SK海力士与美光同步扩产，供需缺口可能继续推高手机和内存价格",
  "meta": {"source": "公开资料整理", "date": "YYYY-MM-DD"},
  "sections": [
    {
      "title": "行业产能格局",
      "tag": "产能格局",
      "tone": "blue",
      "cards": [
        {"label": "供给结构", "text": "以统一口径呈现公开产能信息。"}
      ]
    }
  ]
}
```

`single` 不要求 `audience`，输出 `input.png`。如果输入含评级、估值、目标价、交易建议等投资敏感内容，渲染器会拒绝生成，提示改用 `dual` 或重新确认。

## 标题与副标题

标题与副标题共同服务两类阅读动机：只有少量金融知识的泛金融读者需要迅速看懂“谁提出、和我有什么关系、可能影响什么”，深度读者需要通过具体对象、变量、事实或结论判断内容价值。两层合起来完成任务，不要求每一层单独答全。

写标题前，先从源文档提取：原标题、核心观点责任主体、姓名或机构名、与主题直接相关的身份依据、作者明确结论，以及至少一个有来源支撑的专业锚点。姓名或机构已知但身份不明时，可用所属机构官网、作者主页、报告署名页等一手来源核实；查不到不猜。

### 标题（title）

主标题负责吸引阅读。作者可确认时，使用：

`相关领域身份 + 姓名/机构名：作者明确的核心判断或读者影响`

- **责任主体必须准确**：研究报告取作者或研究机构；演讲、访谈取发言者或受访者；新闻事实报道取记者或媒体；资料汇编取整理机构。不能把转述者写成观点提出者。
- **姓名优先保留**：个人身份压缩为与主题有关的“领域 + 角色”，如`全球航运分析师王明`；不得只写一个默认读者认识的陌生姓名。完整职位过长时删除机构层级和无关头衔，但不能拔高资历。
- **机构名优先保留**：没有个人署名时使用机构名。陌生机构只补一个说明“做什么”的短身份，如`芯片研究机构TechInsights`；不得添加权威、顶级等评价。
- **多人署名只留主责**：保留第一作者或主要责任人并加“等人”；无法判断主次时使用团队或机构名，不并排罗列姓名。
- **无法确认就省略**：作者身份是必须调查的信息，不是允许编造的固定槽位。作者完全无法确认时可以省略，也不必硬塞`未署名报告`；只有未署名会影响可信度时才在副标题说明。
- **归属不能偷换**：只有作者明确提出的判断才能直接放在署名冒号之后。Agent 沿传导链补出的影响应放在副标题，并用`可能`、`风险上升`等与证据相称的措辞。
- **标题长度**：优先不超过 24 个汉字，硬上限 30 个，最多两行。信息放不下时先压缩身份和判断，不能缩小字号，也不能拆散已确认的作者署名前缀。

- 好：`全球航运分析师王明：油轮绕航可能持续到明年`
- 坏：`王明谈全球航运发展趋势`（没有解释王明的身份，`谈`和`发展趋势`没有提供具体判断）

### 副标题（subtitle）

副标题负责补足真实内容：承接主标题放不下的传导关系，同时保留原标题中的研究对象、变量、范围、事实或结论。不得用`原文分析`、`本文讨论`、`报告指出`等元话语介绍内容。

- **至少一个专业锚点**：锚点可以是具体对象、变量、时间范围、事实或结论，必须有源文档或可靠来源支撑；源文档没有就不硬造。
- **优先陈述变量关系**：`红海绕航、油价与全球运力`只有范围，没有说明发生了什么。证据允许时应写成带方向的陈述；原文没有结论或可靠因果关系时，才允许紧凑列举范围。
- **补充而非复述**：副标题不得换词重复主标题。每个短语都应增加作者身份、事实对象、专业锚点、关键机制或读者影响中的至少一项。
- **副标题长度**：优先不超过 44 个汉字，硬上限 60 个，最多两行。英文缩写、数字和标点按实际视觉宽度复核；超行时重写，不靠缩小字号。

- 好：`红海绕航推高运力与燃油成本，运输价格仍有上行风险`
- 坏：`原文全面分析红海局势及其深远影响`（没有具体对象、变量、机制或方向）

### 读者关系与传导链

默认读者是只有少量金融知识的泛金融读者：理解利率、通胀、股价、行业周期等基本概念，但不能假设他了解作者背景、信源机构或专业缩写。

寻找读者关系时按以下顺序选择最短、证据最强的一条主链：

1. 利率、汇率、资产价格、融资成本等明确金融影响。
2. 物价、工资、房贷、存款收益等个人收支与资产负债影响。
3. 就业、订单、行业景气等工作与生意影响。
4. 商品价格、出行、日常产品和服务等消费影响。

**传导链思维**：从行业话题出发，沿因果链条向下游推导，直到触达普通人可感知的生活场景——消费品价格、日常使用的产品或服务、就业机会等。

- 最多推导三跳，副标题不必写出完整链条，但至少保留能解释关系的关键机制。
- 同一标题组只选一条主传导链，优先选择距离最近、证据最强、覆盖读者最广的影响。最多两个终点，且必须来自同一条链并能简短表达。
- 每一跳都要有源文档、常识性经济机制或可靠外部资料支撑。不确定性要如实写成`可能`、`更容易`、`风险上升`，不能把风险写成必然结果。
- 走完三跳仍找不到可信关系时允许不写读者影响，改用具体研究对象、关键变量或事实提供阅读价值；禁止硬扯物价、投资或生活。
- 不强制使用`你`、`你的`。`进口商品可能涨价`已经说明读者影响，通常比`你买东西要多花钱`更准确。禁止`与你息息相关`、`影响每一个人`等空泛关系。

示例：`国际冲突 → 原油供应风险 → 能源与运输成本上升 → 部分商品可能涨价`。

### 一套标准

`title` 和 `subtitle` 同时用于 Internal 与 External，统一避开具体标的的买卖、仓位、目标价和收益暗示。影响终点可落在宏观金融、产业、企业成本、就业、个人收支或消费场景。新生成的 JSON 只写这一组标题，不另写 `external_title` 或 `external_subtitle`。

### 禁止项

- **删除测试**：逐短语删除。删掉后作者身份、事实对象、专业锚点、关键机制或读者影响均未减少的内容，就是废话，必须删。
- **指令回声**：禁止"不需要X，只需要Y""不是X，而是Y""X的本质是Y"等教科书句式，这是 Agent 把内部推理过程直接输出为标题的典型痕迹。
- **设问**：禁止用"为什么""如何""怎样""是否""吗""贵不贵""划不划算"等设问、反问或问号隐藏结论。允许`谁在扩产、谁在抢单`这类准确说明比较对象的范围式表达，前提是正文逐一回答且标题末尾不加问号。
- **破折号**：禁止使用"——"连接前后半句，用逗号。
- **元话语和包装词**：禁止`原文分析`、`本文讨论`、`报告指出`、`这场竞赛`、`这个行业`、`一图看清`、`一文读懂`、`全景梳理`、`深度解析`、`重磅`、`揭秘`、`罕见发声`、`值得关注`等无新增信息的内容。
- **抽象专业词**：`行业格局`、`发展趋势`、`核心逻辑`等词只有在绑定具体对象、变量、事实或结论时才能保留，不能用来冒充专业度。
- **无必要的归因动词**：`警告`、`直言`、`预测`、`反驳`只有在准确表达作者真实立场、且删掉会改变原意时才能保留。
- **跨层重复**：标题和副标题不得换词重复同一信息；副标题必须补充主标题放不下的内容。
- **二元模糊结论**：禁止"是涨是跌""是X还是Y"式正反并列收尾。传导链终点必须给方向性判断（"可能涨""大概率降价"），且该判断要在正文卡片中有依据。
- **名词堆叠**：不得为了缩短篇幅把多个抽象名词并排；优先说明变量之间发生了什么。

## 字段约束

- `meta.date` 和 `share.badge` 禁止 Agent 自行填写，在 JSON 中始终省略。日期必须由用户显式要求后通过 `python scripts/set_date.py <input.json> [--date YYYY-MM-DD]` 设置。渲染器启动时会检查日期是否已设置，未设置则拒绝渲染。
- `output_policy` 必须为 `single` 或 `dual`。省略时默认的 `--mode auto` 会停止渲染，要求先完成策略判断。
- `dual` 模式的 `audience` 只能为 `both` 或 `internal`。省略时按 `internal` 处理，防止误外发。
- `tag` 是左侧浅色标签的短章节名，建议 6-12 个汉字；`tone` 可使用 `blue`、`amber`、`green`、`pink`、`cyan`、`purple`、`orange` 或 `gray`，省略时按顺序循环。
- `blocks` 是章节内的视觉块，目前支持 `type: "table"`。表格使用 `title`、`headers` 和 `rows`；表头数量须与每行单元格数一致，限 2-4 列，每个单元格仅放简短事实或判断。
- `dual` 模式的每个 `blocks` 条目必须显式写 `audience`。External 仅保留 `audience: "both"` 的表格，并会逐格检查敏感词；任何带评级、估值、价格、交易建议或预测性财务信息的表一律标为 `internal`。
- `external_title` 和 `external_subtitle` 仅为旧 JSON 兼容字段；新 JSON 应省略。旧文件提供这些字段时仍会优先用于 External，并接受相同的标题规则与敏感词检查。
- `style.safe_top_px` 限制在 `72-240`；`style.accent` 仅接受 `#RGB` 或 `#RRGGBB`。
- 品牌背景、文案和二维码默认读取 `assets/brand.json`。`footer_intro` 支持用 JSON 转义 `\n` 指定必须保留的真实换行，默认机构介绍固定为两行。 当 `share.override_brand` 不为 `true` 时，`brand.json` 中已存在的字段优先，即使其值为空字符串或空数组；因此默认的 `footer_points: []` 会压制输入 JSON 中遗留的“人 / 事 / 钱”分点。
- 只有设置 `share.override_brand: true`，输入 `share` 中显式出现的品牌字段才覆盖 `brand.json`；未写入的字段仍继承品牌配置。该规则适用于 `masthead_text`、`footer_title`、`footer_intro`、`footer_points`、`footer_background`、`qr_image` 与 `qr_label`，并允许用空字符串或空数组明确清空字段。
- `share.footer_background` 是不含文字和二维码的 1080×400px 底栏背景图片路径；默认使用 `assets/footer-tech-blue.png`。底栏文字与二维码始终由渲染器独立分层，正文与底栏之间固定保留 70px 白色间隔，底栏与间隔合计占用 470px。
- `share.qr_image` 最终解析为空或文件不存在时生成二维码预留位；默认品牌配置使用 `assets/zhifujie-qr.png`，顶部与底部共用同一图片。
- External 不使用卡片 `source`，避免在来源文本中意外带出敏感投资术语。
- `single` 不渲染任何受众标签；`dual` 的内部图由渲染器统一显示“内部研究版”，External不显示受众标签。
- External 忽略 `share.badge`，右上角固定显示 `meta.date`。

## 研报预览横条

必须生成缩略图并在 JSON 中加入 `docx_preview` 字段，在正文与底栏之间插入研报页面缩略图预览横条：

```json
{
  "docx_preview": {
    "dir": "_page_thumbs",
    "pages": 4,
    "thumb_width": 240,
    "total_pages": 42
  }
}
```

- `dir`：页面缩略图目录路径，相对于输入 JSON 所在目录。目录中需包含 `page_01.png`、`page_02.png` 等按页码命名的 PNG 文件。
- `pages`：展示的页面数量，默认 `4`。渲染器每行最多显示 4 张缩略图，超出自动换行；例如 `pages: 8` 会显示为两行。
- `thumb_width`：缩略图嵌入时缩放到的宽度（像素），默认 `240`。仅影响嵌入尺寸，不改变显示尺寸。
- `total_pages`：可选，研报总页数。省略时自动从同目录下的 PDF 文件读取；无 PDF 时退回到目录内的 PNG 文件数。

预览横条在 Internal 和 External 两版中均显示。缩略图缩到 210px 宽后页面文字不可读，不构成合规风险。

渲染器会在启动时检查缩略图是否就绪（`docx_preview` 字段和实际文件），缺少时拒绝渲染。
