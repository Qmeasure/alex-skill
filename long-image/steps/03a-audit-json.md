# 步骤 3a：JSON 合规审计（Sub-agent）

在 JSON 创建完成、渲染之前，启动一个 sub-agent 对 JSON 进行独立合规审查。

## Sub-agent 职责

将以下内容交给 sub-agent：
- 生成的 JSON 文件
- `references/external-compliance.md`
- `references/schema.md`

要求 sub-agent 检查以下维度并逐项列出发现：

1. **audience 标注完整性**（仅 dual 模式）：每个 section、card、block 是否都显式标注了 `audience`；缺失标注的条目列出位置。
2. **混合内容拆分**：是否存在 `audience: "both"` 的卡片中混入了投资动作语言；逐卡扫描，给出具体文本。
3. **External 表面安全性**：`title`、`subtitle`、所有 `audience: "both"` 的标题/正文/表格内容中是否包含 `external-compliance.md` 列出的禁止项；旧 JSON 若有 `external_title`、`external_subtitle` 也要检查。
4. **schema 合规**：`output_policy` 是否存在、`tone` 是否有效、表格列数是否超过 4 列、`meta.date` 和 `share.badge` 是否被手动写入。
5. **信息丰富度**：External 可见的章节和卡片数量是否过少（例如 dual 模式下 `both` 内容不足总内容的三分之一），提示可能遗漏了可公开的事实内容。
6. **标题责任主体**：作者可确认时，主标题是否包含压缩后的相关身份与姓名/机构名；是否把核心观点归给了真正的责任主体；是否把 Agent 推导的影响冒充作者原话；多人署名是否只保留主要责任人或团队。
7. **标题信息结构**：主标题是否优先承载责任主体与核心判断/读者影响；副标题是否承接主标题放不下的关系，并至少包含一个有来源支撑的专业锚点。不得为了满足格式硬造锚点或影响。
8. **读者关系与传导链**：是否面向只有少量金融知识的泛金融读者；是否只选一条距离近、证据强、覆盖广的主链；是否超过三跳；不确定性措辞是否与证据匹配；是否强行假设读者持有某只股票。
9. **长度与跨层重复**：主标题是否优先不超过 24 字且不超过 30 字，副标题是否优先不超过 44 字且不超过 60 字；标题和副标题是否重复表达同一信息。
10. **AI生成痕迹与废话**：扫描标题、副标题和全部卡片，检查以下问题：
   - 指令回声句式："不需要X，只需要Y""不是X，而是Y""X的本质是Y"
   - 设问词："为什么""如何""怎样""是否""吗""贵不贵""划不划算"
   - 破折号"——"连接前后半句（副标题应使用逗号）
   - 元话语与包装词："原文分析""本文讨论""报告指出""这场竞赛""这个行业""一图看清""一文读懂""全景梳理""深度解析""重磅""揭秘""罕见发声""值得关注"等不承载信息的内容
   - 抽象专业词："行业格局""发展趋势""核心逻辑"等没有具体对象、变量、事实或结论支撑的表述
   - 无必要的归因动词："警告""直言""预测""反驳"只有在删掉会改变作者真实立场时才能保留
   - 二元模糊结论："是涨是跌""是X还是Y"式正反并列收尾；传导链终点必须是方向性判断（"可能涨""大概率降价"）
   - 过度学术化术语：如"二阶导数""一阶导数"等可以用大白话替代的表述
   - 强制第二人称："与你息息相关""影响每一个人"等没有说明具体关系的句式
   - 删除测试：逐短语删除，删掉后作者身份、事实对象、专业锚点、关键机制或读者影响均未减少的内容一律视为废话

## 主 agent 处理方式

Sub-agent 的输出是建议清单。Main Agent 逐条审阅：

- **认同的**：修改 JSON 后继续。
- **不认同的**：忽略，无需解释原因。
- **不确定的**：向用户说明 sub-agent 的发现，由用户决定。

审阅完成并修改 JSON 后，继续步骤 3b（数据可靠性审计）。
