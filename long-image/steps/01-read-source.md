# 步骤 1：提取与阅读源文档

## 创建输出目录

在工作目录下创建 `线图/` 文件夹，后续所有产物均放入此目录：

```
mkdir 线图
```

## 提取源文档内容

调用 Inkstone 技能提取源文档，将产物输出到 `线图/`。

提取完成后，阅读 `source_content.md`（或 `.html`）建立论证骨架。后续步骤 3（创建 JSON）和步骤 3b（数据审计）均基于此文件工作。

## 提取标题与责任主体

在概括内容前，先记录生成标题所需的信息：

- 原标题及其中有信息量的研究对象、范围、变量或结论。
- 内容的核心观点责任主体：研究报告取作者或研究机构；演讲、访谈取发言者或受访者；新闻事实报道取记者或媒体；资料汇编取整理机构。
- 作者姓名或机构名，以及与本文直接相关的“大白话身份”。个人身份压缩为“领域 + 角色”，机构身份只说明“做什么”，不得添加权威、顶级、重磅等评价。
- 作者身份的依据，以及哪些判断是作者明确提出、哪些是后续传导推导。不得把 Agent 推导的影响写成作者原话。
- 至少一个可供副标题使用、且有来源支撑的专业锚点，如具体对象、变量、时间范围、事实或结论。源文档没有就留空，不得硬造。

姓名或机构已知、身份不明时，允许优先查找所属机构官网、作者主页、报告署名页等一手来源。只补与主题相关的身份；仍无法确认时不猜。多人共同署名时保留第一作者或主要责任人并加“等人”；无法判断主次时使用团队或机构名。

## 建立论证骨架

从提取的内容中识别以下维度的信息：

- 公司业务、产品线、技术路径
- 经营数据、行业位置、竞争格局
- 风险和验证点

## 区分内容性质

先区分"业务研究"与"投资判断"。

对含投资建议的章节，进一步拆分：
- 哪些观点是产业事实/数据描述（适合 `both`）
- 哪些是投资动作/配置建议（仅 `internal`）

## 数据时效

- 历史数据必须保留来源日期和口径。
- 金融、市场和时事材料按需核验时效性。

## 禁止项

- 禁止自行填写`meta.date` 和 `share.badge`。日期必须由用户显式要求后，通过 `python scripts/set_date.py` 设置，JSON 中始终省略这两个字段。
