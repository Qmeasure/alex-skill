# 步骤 3b：数据可靠性审计（Sub-agent）

在步骤 3a（合规审计）完成且 Main Agent 已修改 JSON 之后，启动一个 sub-agent 对数据可靠性进行独立审查。不可与 3a 并行，3b 必须基于 3a 修改后的最终 JSON。

## Sub-agent 输入

将以下内容交给 sub-agent：
- 提取的源文档内容（`source_content.md` 或 `source_content.html`）
- 生成的 JSON 文件
- 标题中作者身份所依据的一手来源（如使用）

## Sub-agent 职责

### 第一步：溯源比对

先检查标题与副标题，再逐卡片、逐表格检查 JSON 中的每条数据：

1. **责任主体与身份**：姓名/机构、相关领域身份和观点归属是否有源文档或一手来源支撑。Agent 推导的影响不得冒充作者明确结论。
2. **专业锚点与传导链**：副标题中的具体对象、变量、事实、结论和每一步因果关系是否有依据；标出哪些来自源文档、哪些是 Agent 新增推导。
3. **有源文档支撑**：在 `source_content` 中能找到对应信息。标注原文位置（页码或章节）。
4. **Agent 新增**：在 `source_content` 中找不到对应信息。进入第二步核实。

### 第二步：联网核实

对所有「Agent 新增」的数据，使用 WebSearch 联网搜索验证：

1. **已核实**：找到可靠来源，标注出处（URL 或来源名称）。
2. **存疑**：未找到可靠来源，或搜索结果与 JSON 数据矛盾。标记为存疑。

## Sub-agent 输出格式

以清单形式报告，每条数据标注状态：

- `[源文档]` 章节标题 → 卡片标签：数据内容（源文档第 X 页）
- `[已核实]` 章节标题 → 卡片标签：数据内容（来源：URL 或名称）
- `[存疑]` 章节标题 → 卡片标签：数据内容（原因说明）
- 标题和副标题按同样格式列出作者身份、专业锚点、核心判断和传导链各环节。

## 主 agent 处理方式

- **`[源文档]` 和 `[已核实]`**：无需处理。
- **`[存疑]`**：向用户逐条展示，说明存疑原因，由用户决定保留、修改或删除。不得自行处理存疑数据。
