# 剪映草稿生成规则

使用 PyPI 发布的 `pyJianYingDraft==0.3.0`。该依赖采用 [Apache-2.0](https://raw.githubusercontent.com/GuanYixuan/pyJianYingDraft/main/LICENSE) 许可证；不要复制其他参考仓库中的剪映封装代码。

## 草稿内容

- 合成音轨：一条音频轨。
- 多人分轨：每位嘉宾一条音频轨，轨道名取当前审核页中的嘉宾名。
- 不创建视频轨、文本轨、字幕轨、贴纸或其他视觉素材。
- 不生成 FCPXML，也不渲染成品音频或视频。

每个连续保留的来源区间对应一个独立 `AudioSegment`：

- `source_timerange` 指向原文件中的实际起点和时长。
- `target_timerange` 使用剪辑后的起点和时长。
- 全局删除的时长从后续所有轨道的目标起点扣除。
- 单轨删除只切开对应嘉宾的片段，不改变全局目标时间。

草稿不得只放一段覆盖完整原文件的音频，也不能把所有保留区间先渲染成一个新文件再导入。

## 切割结果来源

导出接口必须收到当前 `revision` 和 `planId`。服务端核对无误后，直接读取该 `cutPlan` 中的轨道和片段，不得在导出阶段重新按词条时间戳或波形计算边界。

- 合成音轨使用 `cutPlan` 的一条来源轨道。删除段作用于整条波形，包括区间内的重叠讲话。
- 多人分轨按 `cutPlan` 分别写入每位嘉宾的轨道。全轨删除影响所有轨道的 `target_timerange`；单轨删除只切开对应嘉宾的来源片段。
- `cutPlan.globalDeletions` 记录全轨删除，`speakerDeletions` 记录单轨静音，`tracks` 给出每个 `sourceId` 最终写入的片段。导出器直接消费 `tracks`，不从前两项重新推导片段。
- 手动切点已经包含在 `cutPlan` 内。剪映片段的 `source_timerange` 必须与页面波形和精确试听中的实际边界相同。
- 导出过程中发现项目版本、音频文件指纹或 `planId` 变化时立即停止，不生成部分草稿。

`needsReview` 为真的删除段可以保存和试听，但用户尚未确认切点时不能声称剪辑已经准确。导出前页面应提示用户复核这些区间；后端始终保护相邻未选词，不为消除残音扩大到安全范围之外。

只要 `cutPlan.deletions` 中存在 `canCut: false`，导出接口就返回 `409 uncuttable_selection`，不能生成草稿。用户调整选词并得到全部可切的新 `planId` 后才能导出。`canCut: false` 的区间不会出现在实际删除范围或轨道片段切口中。

淡入淡出只加在相邻保留片段的接缝处，用于减少爆音。它不能扩大、缩小或掩盖删除区间，也不能替代完整的语音边界判断。

## 草稿目录

Windows 上先读取命令行 `--draft-root`，再读取 `JY_PROJECTS_ROOT`。两者都没有时，才按剪映专业版 5.9 的常见用户目录检测；检测不到就停止并要求用户指定，不能把草稿写到猜测的路径。

草稿直接引用输入音频的绝对路径。导出前确认文件存在，导出后提醒用户不要移动或重命名这些文件。

结构检查只能确认 JSON、轨道、片段数量和时间范围符合计划。只有在 Windows 剪映 5.9 中实际打开并试听后，才能声称完成剪映人工验收。
