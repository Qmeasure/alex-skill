# 剪播客

把播客音频转成逐字审核项目。用户确认删词后，生成由多个音频片段组成的剪映草稿。

## 先判断输入

- 只有一个音频文件：按合成音轨处理。立体声也不拆左右声道。火山引擎负责区分说话人。
- 有两个或更多音频文件：按多人分轨处理。每个文件对应一位嘉宾，文件顺序就是默认嘉宾顺序。
- 输入是视频：停止本流程，改用 `chengfeng-videocut-skills:剪口播`。

多人分轨必须从同一时间点开始、时长一致。脚本按各文件的编码帧时长判断误差；超过其中最宽的一帧就停止，不裁尾，也不补静音。

## 准备环境

日常完整流程在 Windows 上运行，目标版本为剪映专业版 5.9。Python 必须是 3.10 或更高版本，先运行 `py --version` 确认版本，再安装依赖：

```powershell
py -m pip install -r <SKILL_ROOT>\requirements.txt
```

系统还需提供 `ffmpeg` 和 `ffprobe`。火山引擎密钥按以下顺序读取：

1. 环境变量 `VOLCENGINE_API_KEY`
2. `<SKILL_ROOT>/.env` 中的 `VOLCENGINE_API_KEY`

不得把真实 `.env` 加入仓库、日志或聊天内容。安装或更新 Skill 时也要排除 `.env`。

## 工作流程

### 1. 转录并建立项目

```powershell
py <SKILL_ROOT>\scripts\podcast_editor.py prepare `
  --input "D:\audio\mix.mp3" `
  --workdir "D:\output\剪播客"
```

多位嘉宾分轨时重复传入 `--input`：

```powershell
py <SKILL_ROOT>\scripts\podcast_editor.py prepare `
  --input "D:\audio\guest-1.wav" `
  --input "D:\audio\guest-2.wav" `
  --workdir "D:\output\剪播客"
```

未给 `--workdir` 时，脚本写入 `~/Desktop/output/<时间>_<文件名>/剪播客/`。项目文件及字段见 [references/project-contract.md](references/project-contract.md)。火山引擎请求参数见 [references/volcengine-asr.md](references/volcengine-asr.md)。

### 2. 通读逐字稿并预选口误

建立项目时，先选中独立词条“呃、啊、嗯、额、哦、哎、呐”。连续出现时每个词条都选中，不需要结合上下文保留。

再读取完整逐字稿，结合前后句判断其他口误，只标记把握高的内容：

- 明确说错后重新说了一遍的片段
- 紧邻的重复词或重复短句
- 没说完就放弃的残句
- 明显卡顿或结巴重复
- 没说完的短句或只剩语气的一整句

不要处理背景底噪，不要缩短自然停顿，不要改写原话。多人对话中，先确认同一时间有没有其他嘉宾讲话。没有重叠时全轨删除；有重叠时只去掉说错者轨道的声音。具体判断见 [references/cutting-rules.md](references/cutting-rules.md)。

把确认过的词条 ID 写入 JSON 数组，再通过脚本导入。不要直接修改 `review-state.json`：

```powershell
py <SKILL_ROOT>\scripts\podcast_editor.py seed-selection `
  --project "D:\output\剪播客" `
  --from-json "D:\output\剪播客\selection-seed.json" `
  --mode replace
```

`selection-seed.json` 可以直接是词条 ID 数组，也可以使用 `{"selectedWordIds": [...]}`。脚本会拒绝不存在的词条，并通过同一套状态保存逻辑递增版本号。

### 3. 启动审核页

```powershell
py <SKILL_ROOT>\scripts\podcast_editor.py serve `
  --project "D:\output\剪播客" `
  --draft-root "D:\JianyingPro Drafts"
```

打开命令输出的本地地址。页面上方显示当前嘉宾和字幕，下方按嘉宾轮换组织完整逐字稿。同一嘉宾连续说话时保持在同一段，只在嘉宾切换时换段。标点只用于阅读，不参与选择和剪辑。

用户可以逐字增删、撤销、重做、筛选嘉宾、修改嘉宾名，也可以为某轮发言重新指定嘉宾。火山引擎的说话人识别可能把音色相近或很短的发言归到同一人；遇到自我介绍、互相点名等明确证据时，在该轮左侧改正，不要改原始转录文件。

连续选中的词之间只要没有未选词，就属于同一个删除段。词间停顿和识别留下的时间空档也随该段删除，不能因为空档超过某个时长而重新保留。服务端结合字级时间戳和真实波形确定切点；自动切点不合适时，可在波形上调整删除段的左右边界，也可恢复自动结果。

每次保存后，本地服务返回新的 `cutPlan`。即时播放、精确试听和剪映导出都使用这份结果；播放器不会在页面内另算删除范围。多人分轨即时播放按来源文件分别读取音频，并按 `cutPlan.tracks` 同步各轨道。播放中改词时，页面先静音，收到新 `cutPlan` 后再从相同的剪后时间继续。上方字幕只显示保留内容，下方逐字稿继续显示删除线。“生成精确试听”只在用户点击时渲染，编辑后不自动重建。

自动分析找不到稳定静音，或选中文字与相邻保留词连读时，页面必须显示切点复核提示。此时不能把字级时间戳称为精确切点，也不能越过相邻保留词强行扩大删除范围；用户应在波形上检查并手动调整。

安全范围无法完整覆盖原始选词时，删除段返回 `canCut: false`。这段声音和上方字幕都保留，波形手柄禁用；精确试听和剪映导出返回冲突错误。用户必须调整选词，直到所有删除段都能安全切除。

所有改动由本地服务保存；页面不自行计算剪辑区间，也不显示虚构的处理进度。

### 4. 用户确认后导出

用户点击“导出到剪映”后，本地服务直接写入剪映草稿目录。草稿只含音频轨，不含字幕轨、视频、FCPXML 或渲染后的成品音频。

导出完成后只回复：

```text
剪映草稿：<草稿名称>
目录：<草稿绝对路径>
```

不要把转录 JSON、审核状态或临时混音列为交付物。剪映片段与删词区间的对应规则见 [references/jianying-draft.md](references/jianying-draft.md)。

## 必须遵守

- 输入模式只看文件数量，不能按声道数量判断嘉宾。
- 一个合成文件只转录一次，且关闭声道拆分。
- 多人分轨逐文件转录，再按时间合并；导出时仍保留独立轨道。
- 嘉宾名只是显示名称，内部说话人 ID 不能随改名变化。
- 前端只提交所选词、嘉宾名称和句段的嘉宾修正。保存、轮次合并、时间区间计算、预览和导出都由后端完成。
- 前端调整切点时只提交 `cutOverrides`。后端负责检查调整范围，并生成新的 `cutPlan` 和 `planId`。
- 连续选中的词之间没有未选词时，必须连同中间的停顿一并删除。未选词才会把删除段断开。
- 自动切点要根据持续低能量区判断完整起声和收声，不能把单个低能量采样帧当作可靠边界。
- `needsReview` 为真时必须显示 `boundaryWarning`，让用户在波形上确认切点。没有可靠静音时不能假装已经精确切除。
- `canCut` 为真时，实际删除范围必须完整覆盖原始选词范围；为假时不能删除声音、隐藏字幕或开放手动切点。
- 即时播放、精确试听和剪映导出必须使用同一 `planId`。版本或 `planId` 不一致时停止生成，要求页面先取得最新状态。
- 多人分轨即时播放必须逐个读取 `playback.sources`，并逐轨使用 `cutPlan.tracks` 中的保留片段，不能只播放临时混音来冒充逐轨结果。
- 每个连续保留区间必须成为独立 `AudioSegment`，不能把未剪的完整音频放进草稿。
- 草稿引用原音频绝对路径。导出后不得移动或重命名原文件。
- 没有有效火山引擎密钥时，明确说明转录未验证；不得用模拟数据冒充结果。
- 没有在 Windows 剪映 5.9 中打开草稿时，只能说明结构检查通过，不能声称剪映已人工验收。
- 本地审核服务只监听 `127.0.0.1`，不得对局域网或公网开放。
- 参考其他开源项目时只采用可独立实现的处理原则。不得复制 AGPL 项目的源码或模板。
