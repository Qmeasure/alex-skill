# 输入归一化

先把输入恢复成标题、段落、列表、引用、表格、脚注、链接和来源位置，再生成 HTML。归一化只修复结构，不改写内容。

## 通用记录

处理每个内容块时保留：

- 内容类型；
- 原始文字；
- 原始顺序；
- 文件名及页码、章节或段落位置；
- 链接地址、脚注编号和表格单位；
- OCR 产生的疑似错误。

无法确认的文字和数值保留原样并标记位置，不按上下文猜测。

## Markdown

- 保留 `#` 至 `####` 的标题层级。开头唯一的 `#` 一级标题是文章标题，读出来供交付说明使用，不进正文。
- 保留段落、列表、引用、围栏代码、表格、链接和脚注。
- 图片语法不进入 HTML。保留替代文字、题注和可用的来源链接。
- frontmatter 只用于识别标题、作者、日期和来源，不整块写入正文。

## HTML

- 读取可见内容和语义标签，丢弃原有主题 CSS、脚本、导航、广告和交互控件。
- `h1` 至 `h4`、`p`、列表、引用、表格和链接映射为相同语义。页面上的文章标题（通常是首个 `h1`）不进正文。
- `div` 和无语义 `span` 只作为分组依据，不直接复制到正文。
- 图片、背景图、SVG 和 Canvas 不进入正文。保留附近题注、替代文字和来源链接。
- 不沿用输入 HTML 的颜色、字体、阴影、定位和响应式规则。

## DOCX

- 使用文档读取工具或 `python-docx` 读取段落、标题样式、列表、表格、超链接、脚注引用和原始顺序。
- 标题样式映射到对应标题层级；普通段落不能因为字号较大就自动升级为标题。
- 表格保留合并单元格、表头、单位和脚注。先还原为数据表，再判断是否适合转为图表。
- 对内嵌文字图片和图表截图运行 Tesseract，语言使用
  `chi_sim+chi_tra+eng`。OCR 结果必须对照图片复核数字、负号、小数点、百分号和单位。
- 照片或无法读取内容的插图只保留原题注、替代文字和所在位置。

## PDF

1. 先读取文本层，记录页码。
2. 删除重复页眉、页脚和纯页码行。
3. 合并由版面造成的硬断行，不合并原本分开的段落。
4. 识别双栏顺序；文字前后不连贯时按版面重新排列，不能按语义补句。
5. 没有文本层的页面用 PyMuPDF 渲染，再用 Tesseract
   `chi_sim+chi_tra+eng` 识别。
6. 图表截图先读取标题、轴、图例、数值标签、单位和来源。只有数据能够逐项确认时才重建图表；否则保留题注、替代文字、页码和来源。

OCR 后重点检查：

- `0/O`、`1/l/I`；
- 负号、百分号和小数点；
- 中文单位与英文缩写；
- 表格列错位；
- 图例与数据系列错配。

## 纯文本

- 空行用于分段。
- 原文已有的编号、章节目次和短标题用于恢复标题层级。
- 行首项目符号和连续编号用于恢复列表。
- 不根据文章意思自拟标题、摘要或结论。
- 无法确认标题层级时，保持普通段落，不升级为标题。

## 结构整理的边界

可以：

- 修复明显错误的标题级别；
- 合并 PDF 硬断行；
- 拆开因复制而粘连的列表项；
- 把可确认的表格恢复为行列；
- 将符合规则的数据表转换为图表。

不可以：

- 改写句子；
- 调换论证顺序；
- 合并意思相近的段落；
- 删除重复表述；
- 补充缺失标题或数据；
- 根据上下文修正未经核实的数字。
