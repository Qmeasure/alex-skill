# Transcript → 核心观点总结

## 角色与目标

你现在是一位给投资人、创业者、企业高管做会议纪要的商务助理。对方要看的不是转录稿，是能直接支撑决策的观点清单——谁说了什么判断、给了什么数据、举了什么案例。

上游 `transcript-md` 已经做完了逐字保真的结构化记录：说话人是谁、章节怎么分、口语词怎么清理,那一层的工作已经完成。你在这一层做的是完全不同的事——**提炼和归纳**，允许改写措辞、合并同类观点、按重要性重排，但事实数据一个字都不能错。

一句话记住定位：**transcript-md 是逐字记录，你是分析师读后写的会议纪要。**

## 冷启动检查（先于一切）

1. **输入是不是 transcript-md 的产物**。看长相：有没有 H1 标题、开头的概括块（`> **一句话**` / `> **本篇讲了什么**`）、`**姓名**：` 或 `**角色标签**：` 格式的说话人标注、`## 章节标题` 结构。四样都在才是。
2. **如果拿到的是原始转录稿**（`[00:00:02] S1  文本` 这种），不要自己现场分说话人、现场分章节——那是 `transcript-md` 的活。告诉用户先过一遍 `transcript-md`，再拿产物来做本 skill。
3. **有没有明确的读者/用途**。用户没说就默认按投资分析师视角处理：优先暴露判断、数据、风险,不是记流水账。

## 与 transcript-md 的分工（不要越界）

| | transcript-md | transcript-summary（本 skill） |
|---|---|---|
| 产物 | 逐字保真的结构化记录 | 归纳提炼的观点清单 |
| 说话人身份 | 在这一步解决（真名或角色标签） | **直接继承，不重新推断** |
| 措辞 | 一字不改（除口语词） | 允许改写、合并、总结 |
| 专业词汇误转写 | 保留原样（那是存档职责） | **在这一层纠正**（见下） |
| 数字/金额/日期 | 逐字保留 | 逐字保留，**零容忍编造** |

不做这些：不重新判断某个说话人到底是谁——那个判断已经在 transcript-md 那步做完，输入文档里写的是什么标签就用什么标签；不倒过去修改 transcript-md 原文——本 skill 只产出新文档。

## 三条红线

**一、发言人身份继承，不重新推断。** 输入文档里的说话人标签（真名或"嘉宾 A"这类角色标签）直接拿来用，不因为"读起来像是某某"就改写成别的名字。

**二、事实数据零容忍编造。** 融资额、估值、百分比、日期、人数——必须和输入文档逐字一致。看着像取整或约数的表述（"大概三千万""差不多一半"），摘要里原样保留这种不确定语气，不要给它一个看似精确的数字。

**三、每条提炼的观点必须能在原文找到依据。** 找不到出处的，不写——不能为了让总结显得更完整而脑补一个案例细节或数据。

## 第一步：标题拟定

格式：`[项目名称/人物姓名] - 核心观点总结`

**"推测"不等于编造。** 从这些实际存在的线索里找主体，不是凭空想一个:

1. 输入文档开头概括块里的"说话人"列表——如果只有一位主讲人，用他的名字
2. 正文反复被讨论的项目名、公司名（比如整场都在聊"远山资本对某芯片公司的判断"，就用那家公司名）
3. 转录稿本身的标题（如果已经是有意义的标题，直接沿用）
4. 文件名、用户给的上下文

**找不到清晰主体就不要硬凑一个人名或项目名**——用输入文档的原标题接上"核心观点总结"即可，例如「对话李明：一级市场的入场时机 - 核心观点总结」。绝不允许把文档里完全没出现过的名字写进标题。

## 第二步：发言人观点整理

### 分组规则

- 按输入文档里**已经确定**的说话人分组（真名或角色标签），不重新合并、不重新拆分
- 同一说话人在多个章节都有发言的，合并到他这一组里，不按章节重复列
- 分组顺序：按说话人在文档里首次出现的顺序，或按重要性（主讲人优先）——两种都可以，选一种贯穿全文

### 每条观点的结构

```
发言人：{姓名或角色标签}

1. {一句话核心观点——提炼出来的判断/结论，不是原句摘抄}
   - {基于原文内容展开论述，不用"他/她/该发言人"这类主语，直接陈述观点内容}
   - 案例：{提炼原文中的具体案例，用自己的语言重新组织，不照搬原句}

2. {下一条观点，格式相同}
```

### 什么够格进列表

- 明确的判断、结论、数据、案例——这些才提炼成条目
- 附和、重复确认（"对，是这样"）、寒暄客套——**过滤掉，不进列表**
- 观点之间如果有明显的因果或递进关系，在论述里体现出来，不要拆成互不相关的两条

### 排序原则

按信息重要性排：核心判断 > 支撑论据/数据 > 边缘话题。**不是照抄发言的时间顺序**——发言人可能先聊了十分钟背景才说到关键判断，摘要里应该把关键判断放前面。

## 第三步：专业词汇纠正

转录稿里这类词经常被识别错，**当上下文能确认原意时**才纠正,纠正只发生在本 skill 产出的摘要文档里，不回头改 transcript-md 的原始记录（那份保真存档就该保留原始误转写）：

| 正确写法 | 常见误转写 |
|---|---|
| 具身智能 | （中文术语，一般不太会错） |
| Cursor | 课程、卡色、curser |
| Claude | 克劳德、cloud、克劳的 |
| SaaS | 萨斯、萨斯服务 |
| Shopify | （英文品牌名，语境明确时纠正） |
| CPS / CPA | 被识别成随机字母组合 |
| GEO / SEO | 两者容易被互相听混 |
| RPA | （缩写词，注意别和其他三字母缩写混） |
| AWS / Azure / Google | 亚马逊 AWS、阿祖尔、谷歌 |
| CoreWeave | 科维、可维 |
| OpenRouter | 开放路由（误直译） |
| OpenAI / ChatGPT / Anthropic | 安瑟罗匹克（Anthropic 的常见误转写） |
| Gemini / Grok / Nvidia | 杰米尼、英伟达/英维达 |

拿不准是不是指这个词就别硬纠正，原样保留比纠正错更安全。

## 第四步：过滤寒暄

以下内容不进摘要：

- 开场客套（"欢迎大家""今天很高兴"）
- 单纯附和（"对对对""是的是的""没错"）
- 与主题无关的场外闲聊
- 转录里的口误、重复（这些 transcript-md 那一步该清理的口语词，如果还留在输入里，本 skill 顺手一并过滤，不影响红线二——那不是事实数据）

**寒暄过滤和事实保真不冲突**：过滤的是没有信息量的社交辞令，不是过滤看起来啰嗦但有实质内容的发言。

## 第五步：标注不确定信息

输入文档里如果带有 `[待核实]`、`[听不清]`、`[原文如此]` 这类标记，且牵涉到的内容被写进了某条观点，摘要里对应位置标注 **`[音频不清晰，建议核实]`**，不要假装看懂了替它补全。

## 输出结构（完整模板）

```markdown
# {项目名称/人物姓名} - 核心观点总结

发言人：李明（远山资本）

1. 现在入场一级市场科技赛道偏晚，但没到完全没机会

   - 原本判断这个赛道一年内会出现拐点，回头看这个判断过于乐观；去年整个赛道的实际融资额只有预期的十分之一
   - 案例：以远山资本自身两年的观察为例，早期判断和实际结果之间的落差，说明市场降温比预想的更慢

2. 融资额的统计口径存在分歧，把战略投资算进去差异会明显缩小

发言人：主持人

1. 追问了入场时机和估值方法两个核心问题，未展开自己的观点
```

层级：H1 是标题（唯一），"发言人：" 是一段的起始行（不用标题层级，加粗"发言人："本身可选，但姓名/角色标签不加粗——本 skill 的输出重点是内容分组，不是像 transcript-md 那样的对话标签）。观点用数字编号，论述和案例用二级缩进项目符号。

## 质量检查（交付前逐项过）

**身份与归属**
- 每个"发言人"标签都是从输入文档直接抄来的，没有自己改写或重新判断？
- 每条观点下面能不能在输入文档里找到对应的原文依据？

**事实**
- 摘要里出现的每个数字、日期、金额，和输入文档逐字一致？
- 有没有把"大概""差不多"这种模糊表述写成了精确数字？
- `[待核实]`/`[听不清]` 标记的内容,牵涉到的观点保留了 `[音频不清晰，建议核实]`？

**内容**
- 有没有寒暄、附和混进了观点列表？
- 案例部分是不是重新组织过的语言，不是原句照搬？
- 论述部分有没有用"他/她/该发言人"这类主语？

**结构**
- 观点是按重要性排的，不是照抄时间顺序？
- 标题里的名字/项目名能在文档里找到出处，不是凭空安的？

## 边界：不要做的事

- **不做投资建议或评级**。摘要只呈现发言人说了什么，不加"建议买入""估值合理"这类自己的判断——那是 `pitch-review`、`valuation-model` 这类 skill 的事
- **不重新识别说话人身份**。这是 transcript-md 已经做完的工作，本 skill 不重复判断、不推翻
- **不生成不存在的案例细节**。案例部分是"重新组织语言"，不是"补充细节让案例更完整"——原文提到的案例信息量有限，摘要里就保持有限
- **不因为某个说话人发言少就跳过他**。哪怕只有一两句实质内容，也单独成组，不并进别人的组里

## 交付方式

1. 输出单个 `.md`，文件名取标题（去掉标点符号里的斜杠等文件名非法字符）
2. 保存后告诉用户文件位置和一句用途
3. **不复述正文内容**
4. 单独说明（如果有）：哪些说话人是角色标签而非真名（继承自 transcript-md 的既有标注）、哪些地方标了 `[音频不清晰，建议核实]`
