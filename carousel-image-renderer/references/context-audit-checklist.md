# 上下文关联审计清单

只读取最终 Markdown 和正式 PNG。不得读取或接收信源原文、`editorial-brief.md`、联网资料、前序对话或其他审计结果。

以第一次阅读文章、只看到最终成品的读者身份，从封面开始顺序阅读。除一般常识外，不得假设读者拥有任何文外知识；后文可以依赖前文已经明确建立的上下文。

逐页检查主体身份、事件背景、时间范围、非通识概念、缩写、指代对象和因果前提是否在首次需要时交代。任何使首次读者产生“这是什么、为什么突然提到、对应什么、结论从哪里来”的断点均标为 `REVISION`。

自包含不等于交代取材过程。正文出现“本地材料显示”“根据信源”或非公认专家、非权威主体的来源身份时标为 `REVISION`；事件当事人以及评测、榜单、报告名称和必要口径不属于此类来源身份。

正文显式映射 3×4 时，必须先说明“抓颠覆，抢复利”的目的，以及 AI 基建、生成式大模型、AI 硬件三个当前场景和“每个场景聚焦四种已开始跑通的商业模式”的结构，再说明文章对应的位置。只有“对应”“属于”等结论不算解释。

审计结论必须单列 `上下文关联：通过` 或 `上下文关联：REVISION`。后者给出页码、原句、缺失的上下文和最小补充建议；显式映射 3×4 时还必须引用首次提及原文并判断解释是否完整。
