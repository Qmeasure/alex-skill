# 上下文关联审计

完整阅读本文件夹中的 `article.md`、`manifest.json` 和 `pages/`，以第一次看到成品的普通读者身份，从封面开始顺序审计。

检查：

- 封面是否清楚交代主体、关注理由和阅读承诺，正文是否兑现承诺；
- 主体身份、事件背景、时间范围、非通识概念、缩写、指代对象和因果前提，是否都在首次需要时出现；
- section 之间、续页之间和前后引用是否连续，每一步是否能从已经建立的上下文自然推出；
- 事件、原因、影响以及与泛金融读者的关系是否形成完整、可理解的链条；
- 正文显式映射 3×4 时，是否先完整解释“抓颠覆，抢复利”的目的，AI 基建、生成式大模型、AI 硬件三个当前场景，每个场景聚焦四种已跑通商业模式，以及观察到机会后从挑战龙头、加入龙头、成为龙头的代理或生态伙伴、投资龙头四种个人入场方式中选择路径的结构，再说明本文对应位置。

没有问题时只输出 `PASS`。有问题时按以下字段输出，并合并同一根因造成的连续问题：

- `severity`：`REVISION`
- `category`
- `location`：页码或段落
- `original`：对应原文
- `problem`
- `reason`

只描述问题，不提供解决方案或改写。
