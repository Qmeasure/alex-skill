# 最终审计清单

以只读方式审计已删除 `source_pages` 和末尾 `:::thumbnails` 块的 Markdown 副本、除末页外的正式 PNG、Inkstone 结果，以及实际采用外部资料时生成的 `web-research.md`。不得读取或接收最后一页；只检查提供的成品内容，不审计候选研究过程。

按严重度输出问题、证据位置和修复建议：

- `BLOCKER`：事实错误、来源无法追溯、材料冲突被掩盖、合规或硬验证失败、裁切、错图或无法交付。
- `REVISION`：叙事断点、主体不明、封面弱、文风或组件使用明显不合格。
- `NICE_TO_HAVE`：不影响交付的微调。

## 事实与来源

- 正文是否忠实转述本地信源，并区分事实、预测、观点、估算和援引？
- 多份本地材料存在冲突时，是否按各自原意呈现？
- 实际采用的外部事实是否能回指 `web-research.md` 中的支持内容、链接和访问日期？
- 数字、人物、事件、引用及每段因果关系是否有材料支持？
- 七页正文是否均包含有效信息？

## 定位与表达

- 是否服务泛金融读者并解释潜在影响路径？
- 封面是否说明主体、关注理由和潜在影响，且三层文字不重复？
- section 是否各自推进一个问题，续页是否从完整语义开始？
- 正文是否出现“你”或“本文”，或存在明显翻译腔、报告腔和机械排比？
- 观点与风险是否使用合适组件，数字和强调是否服务叙事？

## 信源呈现（必查）

信源只约束事实和口径，不自动成为正文内容。检查是否把“本地材料显示”“根据信源”或公众号、普通作者、材料搬运者等取材来源身份写进正文；命中后标为 `REVISION`。

区分事件当事人与取材来源：公司或人物作为事件主体可以出现；作为来源署名时，只有公认行业专家，或官方机构、监管部门、公司官方渠道、原始研究机构等权威主体可以保留。评测、榜单、报告名称及其时间、版本和统计口径属于事实语境，不属于来源署名。

审计结论必须单列 `信源呈现：通过` 或 `信源呈现：REVISION`；后者给出页码、原句和删除来源身份后的最小改写。

## 防御性否定（必查）

逐页扫描全部正文，不得省略此项。检查是否用抽象标签加“不等于、不代表、并不意味着”等防御性否定收尾，却没有交代已有证据和缺失证据。疑似命中时读取 [防御性否定示例](defensive-negation-examples.md)；确认空转后标为 `REVISION`，有具体事实作用并紧接证据时保留。

审计结论必须单列 `防御性否定：通过` 或 `防御性否定：REVISION`；后者同时给出页码、原句和改写建议。

## 3×4 证据

正文显式映射时检查：

- 场景、产业环节、资源传导和主要入场方式是否有材料支持？
- 是否把间接受益误写成直接订单或代理关系？
- 是否把高收益主张写成结果保证？

## 机器与视觉

- 硬验证是否通过，正式 render manifest 是否不存在阻断诊断？
- 优先查看 manifest 的 `auditTargets`：封面、最密正文页、risk/callout 页和填充告警页；不得接收 endcard 字段。
- 是否存在溢出、裁切、缺图、乱码、字体问题或不合理空白？
- 分页是否拆坏标题、主体指代或因果链？
- 封面在手机尺寸下是否清楚，组件是否完整留在单页？
- 除末页外的页码和文件顺序是否正确？

没有 `BLOCKER` 或 `REVISION` 时明确回复“通过”。
