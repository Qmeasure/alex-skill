# 嘉宾 pitch + 访谈提纲

三份交付物，一个共同的地基：**把这个嘉宾研究透，然后找出他和智富界真正咬合的地方。** pitch 和提纲都是这一步的产物。跳过它，写出来的就是换个名字也成立的通用稿——嘉宾看两行就知道是群发的。

其中两份是要发出去给嘉宾看的（pitch、提纲外发版），一份只给自己（内部执行版）。**哪句话进哪一份，是这个 skill 里最容易出事的地方**，动手前先把这条界线搞清楚。

## 交付物

1. **嘉宾 pitch 文案** — 一份，600-900 字。**纯文本 .txt，按微信排版，零 markdown**，可带 3-5 个 emoji。完整版等于微信版，不做两份。
2. **访谈提纲（外发版）** — 直接发给嘉宾的。围绕双方定位、共鸣点和这场对话要一起聊清楚什么来写，末尾请他增删。
3. **内部执行版** — 只给自己和主持人看。依据、设计意图、追问句、爆点标注、雷区提醒、待核实清单全在这里。

**默认三份都出。** 提纲的外发版和内部版是一体两面，同时生成，但**必须是两个独立文件、独立成篇**——外发版里出现任何一句内部信息都是事故。

用户只要其中一样就只出那一样，但第 1、2 步不能省——三份东西都从那里长出来。

## 四份参考

开工前按需读：

- `references/six-systems.md` — **六大体系**，我们能讲什么的完整清单。Step 2 找咬合点必读，底部的「内容匹配表」是直接查的：从我们的内容里挑跟这位嘉宾对得上的那几块。
- `references/zhifujie-profile.md` — 智富界事实底稿。pitch 里关于「我们是谁」「我们能给什么」的每一句都必须出自这里，不能临场加工出新成绩。
- `references/interview-craft.md` — 提问手艺。写提纲前必读。
- `references/pitch-craft.md` — pitch 结构与禁忌。写 pitch 前必读。

## Step 0：材料门槛

**材料不够就不要往下走。** 材料决定上限——手里只有一句「某某，某基金合伙人」，写出来的必然是通用稿，写得再漂亮也是废的。

够用的下限是三样都有：

1. 身份与主业（现在在做什么、怎么走到这一步）
2. **至少 3 个具体事实**：时间点、数字、职位变动、代表作、经历过的事件
3. **至少 1 段嘉宾本人的原话或明确观点**——他自己说过的话，不是别人对他的介绍

缺哪样就去补。用户给了链接或账号就抓：WebSearch / WebFetch 找公开报道和文章；tikhub 系列工具抓小红书、微信公众号、微博、B站、YouTube、知乎、Twitter 的账号内容和代表作。抓不到就直接问用户要——**别用行业常识脑补**。

写进三份交付物的每一条嘉宾事实，都必须能指回一条真实材料。查不到、拿不准的，放进内部版的待核实清单交给用户确认——**不要写进外发版和 pitch**，哪怕标着 `[待核实]` 也不行，嘉宾看到的应该是我们确认过的东西。

## Step 1：嘉宾画像

不是简历复述，是找出可对话的地方。整理这几项，每项都标来源：

- **主线**：他这十年在做的一件事是什么，怎么变过
- **具体事实清单**：时间、数字、事件、作品，越具体越好（这是提纲的原料）
- **公开立场**：他反复讲的观点，以及讲这些观点时的语气（有没有情绪、有没有回避）
- **转折点**：材料里出现过的低谷、转向、离职、失败、争议
- **矛盾点**：不同材料里说法不一致的地方，或者说的和做的不一样的地方（金句最容易出在这）
- **他现在想要什么**：在推什么产品 / 内容 / 主张、最近在琢磨什么问题。这决定了 pitch 里的赋能怎么写，也决定 Step 2 挑我们哪块内容
- **缺口**：还想知道但没查到的，列出来给用户

画像是为了知道能跟他聊什么，**不是给他下结论**。写「他 2021 年离职创业做了 X」是事实，写「他属于典型的路径依赖型选手」是点评——后者不该出现在任何一份交付物里，内部版也不要。

## Step 2：咬合点（枢纽）

**从我们能讲什么出发，去够他的背景**，不是拿他的资料去做归类。三步：

1. **看我们有什么** — 打开 `six-systems.md` 的内容匹配表，那是我们的内容供给清单。
2. **挑对得上的** — 挑跟他的**背景**（做过什么、经历过什么）和他**现在想要什么**都对得上的两三块。只对上一件的先放一边。
3. **写成一句话** —

> 我们讲的某条具体判断 × 他做过 / 经历过的某件具体事 = 一个值得两个人一起聊的东西

找 **2-3 个**。这几个咬合点接下来喂三边：pitch 的「为什么是智富界 & 你」直接用；提纲外发版里每条线开头的「为什么想跟你聊这个」由它改写而来；内部版的爆点问题也从它长出来。

三条规矩：

- **写判断，不写体系名。** 「我们体系四讲生态位」是黑话，「能被巨头亲自投钱扶持的生意才跟得上红利」是判断。体系名全篇最多提一次。
- **有分歧就直说，但只在观点层面。** 我们的判断跟他公开讲过的不一样，正是值得聊的地方——被请去附和的人不会认真准备。分歧是对观点，不是对人。
- **不给嘉宾贴标签。** 输出是「我们想聊 X，因为你做过 Y」，不是「你属于某某类型，所以该问你 Z」。后一种写法漏进外发材料，等于当面告诉他我们在把他归档。

挑不出 3 个就写 2 个。一个都挑不出来，说明我们手里的内容跟这位嘉宾接不上——**直接告诉用户，别硬凑**。硬凑的咬合点在提纲里会变成尬聊，在 pitch 里会变成套话。

## Step 3：访谈提纲（外发版）

先读 `references/interview-craft.md`，尤其是「外发版与内部版的分界」那一节——**红线清单在那里，逐条对照着写。**

外发版是给嘉宾看的，它同时在干三件事：让他知道我们读懂了他、让他知道对谁说话、让他有机会改。所以它不是一张题库，是一份**对齐文档**。

写的时候守住这几条：

- **不出现内部术语。** 没有「破冰」「深挖」「爆点」「金句」「设计意图」「依据」这些字眼。分段用内容命名，不用手法命名——写「一、从币圈那轮说起」，不写「第二阶段 经历与深挖」。
- **共鸣写在前面。** 每条线开头一两句说清为什么想跟他聊这个，带上我们真读过的他的东西。这一句是整份提纲最值钱的地方。
- **把材料依据织进问题里，而不是标在旁边。** 内部版写「依据：他 2023 年那条帖子」，外发版写成「你 2023 年说过大模型创业公司九成会死，两年过去了……」——同一个信息，一个是台账，一个是共鸣。
- **敏感问题照问，但要软化并给出口。** 这个嘉宾群体（基金经理、机构人士）最忌讳被突袭，当场只会僵住或者打太极。提前让他看到、给他准备的时间，讲出来的东西反而更实。锋利的措辞和追问留在内部版。
- **末尾必须留三个口子**：想聊而我们没写到的、不方便聊的（直接标出来我们删）、时间形式上的偏好。这是「互相沟通」落到纸面的地方，不能省。
- 埋 2 个智富界受众关心的问题，锚定体系五（尺度错配是亏钱主因）、体系六（能力定位）或体系一（周期阶段判断），具体问法见 `interview-craft.md`。要**明说听众是谁**，让他知道这几个问题是为谁问的，而不是显得我们在套他。
- **六大体系可以点名，但只点一句、不展开。** 可以写「我们自己有一套六大体系的框架，其中一条判断是 X，想拿你的经历来验证或者推翻它」——用具体判断做证，不铺陈六个点。提纲的主角是嘉宾，不是我们的方法论。
- 首期节目留一个问题，请他用自己的话讲这档节目该服务谁——首期需要这个锚。
- 每个问题仍要过**可替换性检验**：换成同行业另一个人还成立的，就是废问题，重写。

## Step 3b：内部执行版

跟外发版同时写，独立成篇。所有从外发版里拿掉的东西都落在这里，不要因为「外发版已经有问题了」就写得潦草——录制当天主持人手里拿的是这一份。

```
# 内部执行版 · <嘉宾名>（不外发）

## 嘉宾速览
<主线、关键事实、公开立场、他现在想要什么>

## 咬合点
<Step 2 的 2-3 条，每条：我们的哪条判断 × 他做过的哪件事 = 能聊出什么>

## 逐题执行卡
对应外发版每一题：

Q1 <外发版问题原文>
    对应内容：<这题背后是我们的哪条判断；纯铺垫题写「铺垫」>
    依据：<来自哪条材料>
    设计意图：<为什么问这个、预期他会给出什么>
    追问：<1-2 句具体的追问句>
    【爆点】<全场标 1-3 个，从咬合点长出来的>

## 现场提醒
- 哪些话题需要给台阶、怎么给
- 他在哪些地方容易背通稿，怎么把他拉回具体事
- 哪个问题问早了会僵，得放到什么位置之后
- 预判他可能在哪几个点讲出可剪辑的话

## 待核实
- <所有 [待核实] 的事实，录前要确认掉的>
```

## Step 4：pitch 文案

**写之前必须完整读一遍 `references/pitch-craft.md`。** 那里有逐段写法、正反例、完整骨架、措辞替换表和跟进话术，不要只看下面这段复述就开写。

**只出一份。** 不做「微信版 + 完整版」，就一份完整版，而它本身要能直接粘进微信。内容和形态冲突时砍内容，不破坏形态。

**六段顺序，硬的**（字数预算见 pitch-craft.md）：

1. 我们读过你什么（120-180 字）—— 三行内证明不是群发
2. **我们是谁·机构**（60-100 字）—— 智富界是什么、多少人什么人、在做什么节目
3. **我们能给你什么**（120-200 字）—— 决定他读不读完
4. **为什么是智富界 & 你**（150-250 字）—— 用 Step 2 的咬合点，决定他要不要认真准备
5. **我们是谁·主理人**（60-100 字）—— 一二级 + 自营基金十余年、9 号牌照，回答「对面接得住吗」
6. 怎么开始（40-60 字）—— 一个他回「行」就能推进的动作

**第 2、5 两处「我们是谁」是两件事**：前者讲机构，后者讲人。机构信息决定他读不读下去，得早给；主理人履历决定他认不认真准备，早给了没人看。把履历提到开头是最常见的死法。

**第 3 段不要重复第 2 段已经报过的规模和人群**，直接写「所以对你意味着什么」。在一条 900 字的微信消息里重复一遍很贵。

**格式：纯文本 .txt，零 markdown。** 出现 `#`、`**`、`- `、表格、`---`、`[文字](url)`，对方微信里看到的就是符号本身。分段靠空行，小标题靠 emoji 起头，列举写「一是……二是……」，引用原话用「」。

**篇幅 600-900 字**，单段不超过 3-4 行，超过 1000 字就砍第 3、5 段的枝节，不砍第 1 段。

**emoji 3-5 个**，一段最多 1 个放段首。用 🎙️ 👋 📌 🤝 ✅ 😄，别用 🚀 💡 ✨ 🔥（发给基金经理显轻浮）。

其他红线：赋能项每一句出自事实底稿，在建的必须标状态；不编造读过的内容；不承诺具体数据；不谄媚不装大；不出现 `[待核实]`。

赋能怎么挑，看对方客观在做什么（这是挑我们手里的东西，不是给对方定性）：

| 他在做的事 | 主打的赋能点 |
|---|---|
| 在做个人 IP 的研究员 / 基金经理 | 精准受众分发、内容素材反哺、二次分发方法 |
| 机构专业人士（不做 IP） | 专业背书、能接住话的对话方、不会被问成外行 |
| 同为内容 / 播客创作者 | 主理人回访互相上节目、渠道联动（注明在接触阶段） |

### 文件

一个 .txt，跟提纲分开：

```
<嘉宾名>-pitch.txt
```

写完在对话里贴一份全文，方便直接复制。

## Step 5：交付前自检

逐条过，有一条不过就回去改。

**先过外发版红线**（这几条任意一条不过，等于把底牌摊给了嘉宾）：

- [ ] 外发版里没有「依据 / 设计意图 / 追问方向 / 爆点 / 金句 / 破冰 / 深挖 / 待核实」任何一处
- [ ] 外发版里没有任何对嘉宾本人的评价和判断（爱背通稿、会回避、需要给台阶……）
- [ ] 外发版里没有百分比控场、没有阶段编号，分段是按内容命名的
- [ ] 外发版每条线开头都写了为什么想跟他聊，且带了我们真读过的东西
- [ ] 外发版说清了听众是谁
- [ ] 外发版末尾留了三个口子（想加的 / 不方便聊的 / 时间形式偏好）
- [ ] 外发版通篇读下来像一份对齐文档，不像一张审问清单

**再过 pitch 的格式**（微信里显形的错误，比内容平庸更致命）：

- [ ] 只出了一份 .txt，通篇没有 markdown：没有 `#`、`**`、`- `、`|`、` ``` `、`---`、`[文字](url)`
- [ ] 分段靠空行，列举写成「一是…二是…」而不是 `-` 开头
- [ ] emoji 总数 3-5 个，一段不超过 1 个，没用 🚀 💡 ✨ 🔥 那一类
- [ ] 六段齐全且顺序正确：读过你 → 我们是谁·机构 → 能给你 → 为什么是智富界 & 你 → 我们是谁·主理人 → 怎么开始
- [ ] 第 2 段只讲机构（社群 + 节目），主理人履历和牌照没有被提前
- [ ] 第 3 段没有重复第 2 段已经报过的社群规模和人群
- [ ] 咬合点每条都能落到一个具体问题上，不是「高度契合」这种场面话
- [ ] 600-900 字，单段不超过 3-4 行

然后过共同项：

- [ ] 每个问题都过了可替换性检验，没有「你怎么看 X」式的通用题
- [ ] 每个问题在内部版里都有依据，依据都指向真实材料
- [ ] 内部版信息完整，录制当天拿着它就能主持
- [ ] pitch 里提到的嘉宾内容全部真实存在，没有一处是推测的
- [ ] pitch 里关于智富界的表述全部出自事实底稿，在建的都标了状态
- [ ] 咬合点是真咬合，不是「都关注 AI」这种谁跟谁都能凑的
- [ ] 每条咬合点都说得出用的是我们哪条具体判断、为什么跟这位嘉宾的背景和诉求对得上
- [ ] 三份交付物里都没有对嘉宾的归类和点评（「某某型选手」「典型的路径依赖」），只有事实和问题
- [ ] 外发材料里的具体数字（估值、营收、市值、回撤幅度）都用 WebSearch 核过时效，核不动的已改成结构性说法
- [ ] 没有把六大体系的报告原文、PDF 或整段表格当附件外发；外发材料里体系只点了一句，没有展开六个点
- [ ] 拿不准的事实都标了 `[待核实]`，且只出现在内部版和给用户的说明里——外发版和 pitch 里一个都不能有（宁可不写这一句，也不能让嘉宾看到我们在猜他）
- [ ] 提纲（外发版和内部版）里没有 emoji——emoji 只在 pitch 里用
