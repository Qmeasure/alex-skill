# Word 文档格式标准

阶段 5 产出的 DOCX 必须符合这份标准。它管排版机制——机构标识、配色、字体、字号、行距、页边距、首页双栏、正文窄栏、表格、图注、页眉页脚、禁止项、交付前核验。研报特有的首页信息编排、Key data 页、章节逻辑由 `../assets/报告模板与版式.md` 管，两者一起遵守；正文字体、字号、行距、颜色以本标准为准。

## 配色

分两套：Word 文字用两档蓝，图表内部用四色板。

**Word 文字与表格**

| 用途 | 色值 |
|------|------|
| H1/H2/H3 标题、表头底色、页眉线、页脚文字、右栏数据值 | 深蓝 `#1B3A6B` |
| 评级与目标价、首页横幅粗线、右栏分隔线 | 亮蓝 `#2B6EF2` |
| 表格隔行底色、目标公司行高亮 | 浅蓝 `#F2F6FC` |
| 来源、口径提示等小字 | 灰 `#666666` |
| 正文 | 默认黑 |

**图表内部**（细则见 `阶段4-图表生成.md`）

| 用途 | 色值 |
|------|------|
| 主数据系列（柱状、目标公司） | 深藏青 `#1F3A6E` |
| 次数据系列（折线）/ 强调 / 负值 | 珊瑚红 `#E15759` |
| 第三系列（堆叠第二层、并列第二组柱） | 中蓝 `#76A9E8` |
| 基准线、辅助线 | 灰 `#9AA5B1` |

图表配色**独立于上面的 Word 文字配色，不共用色值**。柱用深藏青、线用珊瑚红，一冷一暖才拉得开；同色系的柱线组合在小尺寸和黑白打印下分不开，这是踩过两次的坑。珊瑚红在同一张图里只承担次系列、强调、负值三个角色中的一个。旧版的青灰 `#1F4E5F` / `#2F5965` 不得再出现在任何位置，交付前全文搜一遍。

## 机构标识

logo 与机构名是硬要求，任何一页缺失都不算合格。

资产在 `../assets/brand/`，用相对路径引用，不要引工作区外的绝对路径：

- `zhifujie-logo.png` —— 智富界 logo，圆角白底方形图标，本身不含文字，机构名必须另设文本
- `zhifujie-qrcode.png` —— 社群二维码，只用于首页右栏底部；二维码下方居中一行「扫码加入社群」，7pt 灰 `#666666`

**首页顶部品牌横幅**（白底，不加色块）：

- 用无边框一行三列表格排：① logo 1.4 cm 见方 ②「智富界」16pt 加粗深蓝 `#1B3A6B` ③ 右端「首次覆盖研究」+ 报告日期，9pt / 7pt 常规，右对齐
- **logo 和机构名必须分置两格，三格都设垂直居中**。放在同一个段落里做 inline run 会按基线对齐——图片 1.4 cm 高而文字只有 16pt，文字会掉到图片底部，看起来像没对齐
- 横幅下方一条亮蓝 `#2B6EF2` 粗线，粗细 12（1.5pt）。这条线用**表格行的下边框**实现，或者用行距设为 `exact` 的极扁段落；用普通空段落加下边框会凭空多出一行的高度

**正文页页眉**（首页用独立页眉，不重复品牌横幅）：

- 左侧留空
- 右侧 logo 小图标（高 0.5 cm）+「智富界」，9pt 加粗，深蓝 `#1B3A6B`
- 页眉下方一条深蓝 `#1B3A6B` 细线，粗细 4（0.5pt）。这条线用页眉段落的 `pBdr` 下边框实现；首页页眉按规范留空，不带线。交付前由 `scripts/checks/check_rules.py` 断言至少一个页眉部件带这条线

**页脚**：左侧留空，右侧 Word 页码域，9pt，深蓝 `#1B3A6B`。页码必须是域，不是手打数字。

## 字体

全文统一思源宋体（Source Han Serif CN），只用常规和加粗两种字重。

OOXML 层面，每处文字的 `w:rFonts` 三个属性都要设为 `Source Han Serif CN`：

- `w:eastAsia="Source Han Serif CN"`
- `w:ascii="Source Han Serif CN"`
- `w:hAnsi="Source Han Serif CN"`

正文、标题、表格、图注、页眉页脚、脚注，无一例外。

## 页面

- A4，纵向
- 页边距：上 1.8 cm、下 1.6 cm、**左 1.2 cm、右 1.2 cm**
- 页眉、页脚距页边界各 0.8 cm
- **版心宽 18.6 cm = 10546 DXA**（下文所有宽度都以这个为基准）

## 正文与标题

| 元素 | 字号 | 字重 | 颜色 | 行距 | 段前 | 段后 |
|------|------|------|------|------|------|------|
| 正文 | 9pt | 常规 | 默认黑 | 1.25 倍 | 0pt | 3pt |
| H1 | 13pt | 加粗 | #1B3A6B | 1.15 倍 | 10pt | 6pt |
| H2 | 10.5pt | 加粗 | #1B3A6B | 1.15 倍 | 8pt | 4pt |
| H3 | 9.5pt | 加粗 | #1B3A6B | 1.15 倍 | 6pt | 3pt |

正文两端对齐。行距 1.25 是固定多倍值（OOXML `line=300`），不要用"自动"。

## 正文窄栏

**正文文字只排在左侧 12.7 cm 宽的窄栏里，右侧留白 5.65 cm 空着不放任何东西；图表和表格则占满 18.6 cm 版心。** 这是本版式最重要的识别特征，也最容易做反——它不是"给正文加一点缩进"，是正文和图表用两套不同的宽度。

- **正文文字段落**：`indent.left = 142`（0.25 cm）、`indent.right = 3204`（5.65 cm），实际行宽 12.7 cm
- **标题（H1/H2/H3）**：`indent.left = 142`，与正文同左边界；`indent.right = 0`（标题短，不需要限宽）
- **图片、原生表格、图注、来源小字**：`indent` 全为 0，占满 18.6 cm 版心
- 列表段落随正文的左右缩进，编号的悬挂缩进在 142 的基础上叠加

渲染核验时确认：右侧留白带在全部正文页连续不断，没有哪个正文段落漏设 `indent.right`；图表明显比正文文字宽。

## 首页双栏

首页的标题区以下用一个**无边框一行三列表格**承载，不用分节栏（分栏会把页眉页脚一起切开）。

- `tblBorders` 六个方向全部 `none`
- `tblW` 用 `type="dxa"`，等于版心宽度 10546 DXA（18.6 cm）
- 三列 `columnWidths`（DXA）：左栏 7171（68%）、中间留白列 422（4%）、右栏 2953（28%，可用内容宽 4.79 cm）
- 每个 `tc` 必须有 `tcW`，同样 `type="dxa"`
- **三个 `tc` 都要设垂直对齐为顶端**。默认的垂直居中会把较短的那一栏推到中间，两栏起始行错位、上下各留一段空白
- 左栏放报告摘要，右栏放投资数据块，中间列空
- **右栏 `tc` 设左边框**：深蓝 `#1B3A6B`、粗细 4（0.5pt），上下贯穿整个右栏，把投资数据区与左侧摘要分开。这是全文唯一允许出现的竖线——正文表格一律只用横向分隔和隔行底色，不加竖框。交付前由 `scripts/checks/check_rules.py` 断言：这条竖线在位，且全文深蓝竖边框恰好只有这一处

首页必须严格收在一页内。左栏摘要要把版面写满——摘要短了页面下半部会空一大块，那是内容不足，不是留白设计。评级、目标价、当前价、上行空间、AI 研究团队块和二维码一个都不能省。

右栏内部分两个区块，**投资结论区块上方必须有一行「AI 投资建议」标签**（8pt 加粗、亮蓝 `#2B6EF2`，下方一条亮蓝细线）：

```
AI 投资建议            ← 区块标签，8pt 加粗亮蓝，下方细线
  投资评级   增持（首次）
  目标价     US$110.14
  当前价 08-10  US$93.00
  上行空间   18.4%
  ─────────────────    ← 浅灰细线，分开结论与市场数据
  总市值     US$1,323.8 亿
  日均成交 3M  US$7.50 亿
```

评级、目标价、上行空间是 AI 生成的投资结论，总市值和日均成交是市场客观数据，两者必须用这条标签和细线分开——读者要能一眼看出哪些是判断、哪些是事实。

两个区块内部都用第二层无边框表格排「标签 / 数值」两列：

- **标签与数值统一 8pt 常规，两侧字号完全一致，都不加粗**。标签灰 `#666666` 左对齐，数值右对齐
- 层级只靠颜色：评级与目标价用亮蓝 `#2B6EF2`，当前价 / 上行空间 / 总市值 / 日均成交用深蓝 `#1B3A6B`
- 不要给评级和目标价放大字号或加粗。右栏只有 4.79 cm 宽，放大后「增持（首次）」会折行；左右字号不一致会让这一列看着松散

标的未上市时（已申报 / 已过会 / 待发行），右栏元素换成申购建议、合理市值区间、发行后 PE、拟募资额等，相对表现图换成三年营收与净利迷你图——细则见 `../assets/报告模板与版式.md` 的「Pre-IPO / 拟上市标的分支」。

右栏的相对表现图**宽度取满右栏可用宽度**（约 4.7 cm），不要缩小——缩小后图例和刻度看不清，且与右栏其他元素的左右边界对不齐。

**内层表的宽度必须由外层单元格的实际边距推导，不许另写一个数字。** 右栏里的「标签 / 数值」表嵌在右栏 `tc` 内，它的可用宽度 = `COL_R − 该 tc 的左边距 − 右边距`。把这个边距定义成一个常量，同时用于 `tcMar` 和内层表宽：

```
const SIDE_PAD = 200;              // 右栏 tc 的左边距
const KV_W = COL_R - SIDE_PAD;     // 内层表宽由它推导
const KV_L = 1280, KV_R = KV_W - KV_L;
```

两处各写各的数字是踩过的坑：内层表按「减一个边距」算、外层 `tc` 实际留了 200，差出来的 80 DXA 把整块内容顶出版心 4pt，数值贴到页边、标签与数值之间的间距被吃掉，看上去就是文字被挤压。这类错误在 XML 里查不出来（每个宽度单独看都合法），只有量渲染后的词框坐标才发现，交付前由 `scripts/checks/check_render.py` 的「文字未越出版心」断言拦住。

首页页眉用独立首页页眉（docx-js 的 `titlePage: true` 配 `firstPageHeader`），首页页眉留空——品牌横幅在正文流里，不在页眉里。

## 表格

用真正的 Word 表格，固定宽度。

- 表宽：`tblW` 用 `type="dxa"`，**禁止 `type="auto"`**。每张表只有一个 `tblW`
- **表宽一律 10546 DXA（占满 18.6 cm 版心）**，不随列数缩水；两张表拼一行时各 5273 DXA
- 表头：8pt 加粗，底色 #1B3A6B，文字白色 #FFFFFF，居中
- 正文页单元格：8pt，行距 1.15；**Key data 页 7.5pt**（那一页要在单页内装下四块数据）
- 隔行底色 #F2F6FC（首页双栏、双图并列这类外层布局表格除外，它们无边框无底色）
- 对齐按列统一，不按单元格各设：**首列左对齐，其余列一律居中**
- 单元格边距（DXA）：上 80、下 80、左 120、右 120
- **例外**：Key data 页和首页各表用紧凑行高，上下边距 30–40 DXA。这些是密集数据区，按 80 排会撑破单页
- 表格要有 `tblGrid` 和每列的 `tcW`
- 表格所在段落不套用正文的左右缩进
- **表下口径小字放进表内跨列末行**（7pt 灰，`columnSpan` 覆盖全部列），不要写成表格外的独立段落——独立段落会在分页时和表分离，留下孤儿行；并且这行小字要控制在一行以内
- **每一行都设 `cantSplit`**（`trPr` 里的行属性，禁止单行内容被分页切成两半）。不设的后果是页首出现「重复表头 + 一条空行 + 口径小字」的残片——它有文字，空白页断言查不出来，只有渲染后肉眼能看见。设了之后表格仍可能在行与行之间断开，那是正常的续表：`tableHeader` 会把表头带到下一页，续表首行是真数据行，不是空行
- **不要给单元格段落设 `keepNext`（与下段同页）。** 它确实能让整张小表不拆，但 Word 会在这类段落左侧画一个小黑方块格式标记，在单元格里正好贴在文字前面，看上去像给每一行都加了项目符号。宁可让表在行间正常断开，也不要这个标记。同理不用 `keepLines`、`pageBreakBefore`。交付前断言 `document.xml` 里 `<w:keepNext` 出现 0 次

## 图片与图注

**图和表必须占满宽度。** 这是硬规则：任何图片或表格，要么独占一行铺满 18.6 cm 版心，要么和另一张拼成一行各占 9.3 cm。**不允许把图缩小后孤零零居中在页面中间**——那样左右两边各留一条无用的空隙，是整份报告里最显廉价的地方。

- 图片居中：用 `wp:inline`，所在段落设 `w:jc="center"`、`indent` 全 0
- **单图宽度 = 18.6 cm**（@300 dpi 需要 2197 px 源图，生成时按 `figsize` 宽 7.33 in）
- **双图并列**：无边框一行二列表格（`tblBorders` 全部 `none`），每格 5273 DXA，**图宽 9.3 cm 占满该格**（源图 `figsize` 宽 3.66 in）。每图各自的「图表 N」图注在本格图下方。这一行要设 `cantSplit`，否则分页时图和图注会被拆到两页
- 两张原生表格同样可以拼一行，规则相同
- 图注在图片下方，居中，格式「图表 N：<主题>」，8.5pt 加粗，行距 1.15，段前 3pt、段后 6pt
- 来源放在图片**内部**，7pt 常规、颜色 #666666；不要放在图注下方另起一行。原生表格的来源无法放进图内，放表内跨列末行
- 首页右栏的相对表现图不受本节约束——它是封面元素，宽度取满右栏

## 小字

来源、提示这类小字统一 7pt 常规、颜色 #666666。

## 列表与链接

- 列表用真正的 numbering.xml 编号，不要用假项目符号（•、-、*、手打数字、换行冒充列表）
- 超链接写进 document.xml.rels，正文里不出现裸 URL

## 禁止项

- 假项目符号（•/-/* / 手打数字 / 换行冒充）
- 正文、脚注、图表、表格、参考文献里的裸 URL
- emoji
- 静态页码（必须用 Word 页码域）
- 残留的 markdown 标记
- 纯英文名词堆砌的标题
- `tblW type="auto"`
- 旧配色 `#1F4E5F` / `#2F5965`
- 缩小后孤零零居中在页面中间的图或表（要么占满 18.6 cm，要么和另一张拼一行）
- 正文段落漏设 `indent.right`（会把文字铺到 18.6 cm，右侧留白带断掉）
- 任何图表的网格线
- 直角坐标图（柱/折线/面积/散点）的上边线和右边线
- 深色底上直接放 logo（logo 是白底方形，会出现白方块）
- 图片和文字放在同一个段落里做 inline run（基线对齐会让文字掉到图片底部）

## 怎么构建

用内嵌的 `../anthropic_skills/docx/SKILL.md` 生成 DOCX，先完整读取该文件并按其规范操作；其中脚本路径以 `../anthropic_skills/docx/` 为基准。本标准约束的是最终 OOXML 结果，不绑定具体工具——但用 python-docx 时注意它会自动产生 `tblW type="auto"`，要清掉换成 `type="dxa"`。

## 交付前核验（15 步）

按顺序过一遍，任一步不过就回去修，修完重新核：

1. 文件存在、路径可访问
2. DOCX 能解压，核心 XML 可解析
3. `w:rFonts` 的 eastAsia / ascii / hAnsi 三属性都是 `Source Han Serif CN`
4. 表格有 `tblGrid`、`tcW`、单元格边距；每张表单一 `tblW type="dxa"`，无 `type="auto"`
5. 表格对齐正确：表头居中、首列左对齐、其余列居中
6. 列表用真 numbering.xml，无假项目符号
7. 超链接在 document.xml.rels 里
8. 全文无裸 URL
9. 每张图下方有「图表 N：<主题>」，图注下方没有来源脚注（来源在图内）
10. 全文搜不到 `1F4E5F` / `2F5965`；文字配色只有 `1B3A6B` / `2B6EF2` / `F2F6FC` / `666666` / 黑白
11. 正文段落的 `indent` 是 `left=142 right=3204`；图片、表格、图注段落的 `indent` 是 0；表宽全部 10546 或 5273 DXA
12. **把 DOCX 渲染成 PDF/PNG 做视觉核验**（LibreOffice 或 Word），这一步强制，结构校验代替不了
13. 渲染后逐项看：中文显示、表格、图表、页眉页脚、图表编号、图例、标签是否重叠；直角坐标图无上/右边线、无网格线，X/Y 实线在；四色板生效（深藏青 / 珊瑚红 / 中蓝 / 灰），柱与线一冷一暖、一眼能分开，珊瑚红在每张图里只担一个角色
14. 渲染后核版式骨架，六项全过才算合格：
    - **正文窄栏**：文字行宽 12.7 cm，右侧留白带全篇连续不断；图表和表格明显更宽、占满 18.6 cm
    - **无孤立图**：没有任何缩小后居中的图或表，单图铺满、成对的各半
    - **品牌区**：首页 logo 与「智富界」垂直居中对齐，其下无多余空行；每一页右上角都有 logo + 「智富界」；页脚页码域正常递增
    - **首页**：双栏无错位；右栏十元素齐全且顺序为「**「AI 投资建议」标签** → 评级 → 目标价 → 当前价 → 上行空间 →（细线）→ 总市值 → 日均成交 → 相对表现图 → 分隔线 → AI 研究团队块（含二维码）」；右栏标签与数值同为 8pt 常规不加粗、只两种颜色；相对表现图与右栏等宽；二维码下方有「扫码加入社群」；摘要写满版面，含投资建议与风险提示两处 AI 声明；二维码在 100 dpi 渲染图上清晰可扫
    - **第 2 页**：盈利预测及估值摘要表 + 基本状况 + 三表摘要全部收在一页
    - **右栏竖线**：贯穿整个右栏、与内部的横向分隔线不打架；正文里没有别的竖线
    - 表格未在页边界被切断留下孤儿行
15. **跑渲染门脚本**，这一步取代原来靠目视判断的「无空白页」和「首页收在一页」：

    ```bash
    python scripts/checks/check_render.py 输出.pdf
    python scripts/checks/check_rules.py 输出.docx
    python scripts/checks/check_render.py 样张.pdf --sample --pages-min 3 --pages-max 3
    python scripts/checks/check_render.py 输出.pdf --pre-ipo    # 拟上市标的
    ```

    脚本断言五项：页数区间、无空白/近空白页（单页正文字符数 ≥150）、首页元素齐全（AI 投资建议 / AI 研究团队 / 本报告由 AI 生成 / 扫码加入社群 + 评级目标价或申购建议）、首页未溢出（第 2 页剥掉页眉后必须以 `Key data` 开头）、**文字未越出版心**（逐词框比对左右页边距，A4 右边界 561.3pt，容差 1.5pt）。退出码非 0 就不许交付。

    **为什么要有这一步**：首页溢出把内容挤到第 2 页、留下一张近乎空白的页，在开发过程中复发过两次，两次都只有肉眼看渲染图才发现。越界那一项同理——嵌套表格宽度算错 80 DXA，把首页右栏顶出版心 4pt，肉眼只看得出「文字被挤压」，说不出差多少、差在哪，量了词框坐标才定位到。目视不是门，脚本才是。

第 12 步最关键。结构 XML 正确不等于看着对——字体缺失、表格错位、图表标签重叠这些只有渲染出来才看得见。第 13、14 步同样只能靠渲染，XML 里查不出双栏是否错位、图是不是孤零零缩在中间。第 15 步是唯一自动化的那道门，凡它能断言的（空白页、首页溢出、首页元素缺失、页数越界、文字越出版心）都以脚本为准，不接受目视结论。
