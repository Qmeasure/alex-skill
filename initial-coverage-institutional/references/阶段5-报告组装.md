成品 DOCX 必须符合 `Word文档格式标准.md`（机构标识、配色、字体、字号、行距、页边距、首页双栏、正文窄栏、表格、图注、页眉页脚、禁止项），动手前先读那份。研报特有的信息编排（首页三区、Key data 页、章节逻辑）看 `../assets/报告模板与版式.md`，正文排版数值以格式标准为准。

### docx-js 实现要点

这几处最容易做错，写脚本前先对一遍：

- **首页双栏**用无边框一行三列 `Table`（`borders` 六向全 `BorderStyle.NONE`），`columnWidths: [7171, 422, 2953]`（DXA，合计 10546 = 版心 18.6 cm），每个 `TableCell` 必须显式给 `width: { size: …, type: WidthType.DXA }`，并且三格都要 `verticalAlign: VerticalAlign.TOP`（默认居中会让两栏错位）。**不要用分节栏**（`columns`）——分栏会把页眉页脚一起切开。
- **正文窄栏用 `indent.right` 实现**：正文段落 `indent: { left: 142, right: 3204 }`，图片和表格段落 `indent: { left: 0, right: 0 }`。同样不要用分节栏，那会把图表也一起框进窄栏。
- **品牌横幅的 logo 和机构名必须分置两个 `TableCell`，都设 `verticalAlign: VerticalAlign.CENTER`。** 写成同一个 `Paragraph` 里的 `ImageRun` + `TextRun` 会按基线对齐，1.4 cm 高的图片旁边 16pt 的文字会掉到图片底部。
- **横幅下的蓝线不要用独立空段落加下边框**——空段落自带一整行行高，会在 logo 下方多出一行空白。用表格行的 `borders.bottom`，或者一个 `spacing: { line: 20, lineRule: "exact" }` 的极扁段落。
- **首页独立页眉**：`section.properties.titlePage: true`，配 `headers.first`（留空，品牌横幅在正文流里）和 `headers.default`（右上角 logo + 智富界）。漏掉 `titlePage` 会导致首页顶部出现重复的机构名。
- **页眉里的图片**：logo 用 `ImageRun` 放进页眉段落，必须带 `type: "png"`；页眉段落右对齐。
- **正文窄栏**：正文段落 `indent: { left: 142, right: 3204 }`；图片段落、表格、图注段落显式写 `indent: { left: 0, right: 0 }`，不要靠继承默认值。
- **表格双宽度**：`columnWidths` 在表上、`width` 在每格上，两处都用 `WidthType.DXA`（`PERCENTAGE` 在 Google Docs 里会崩）。列宽之和必须等于表宽。
- **底色**用 `ShadingType.CLEAR`，绝不用 `SOLID`（渲染成黑块）。
- **页码**用 `PageNumber.CURRENT` 域，不是手打数字。
- **分页**用 `PageBreak`，且必须包在 `Paragraph` 里。
- 不要用 `\n`——每段一个 `Paragraph`。
- **表下口径小字做成表内跨列末行**（`columnSpan` 覆盖全部列），不要写成表外段落，否则分页时会和表分离；这行小字必须控制在一行内。
- **数值格式化前先判类型**：`_data` 里的「未获取」是字符串，直接套 `toLocaleString` 或乘 100 会渲染成 `NaN%` 落进正式交付物。
- **node 找不到 `docx`** 时先设 `NODE_PATH="$(npm root -g)"`，不要改用别的库或重装。
- **双图（双表）并列的 `TableRow` 要设 `cantSplit: true`**，否则整行会在页边界被切开——图留在上一页，图注被甩到下一页页首，看起来像图注凭空出现。
- 每改一版都要重新渲染成 PDF 逐页看。首页是否收在一页、有没有多出空白页、表格有没有被切出孤儿行，只有渲染能发现。

## 结构

按中式投资逻辑链组织（不是英文研报的固定清单）。骨架见 `报告模板与版式.md`，这里讲每部分放什么、怎么从前序产物取用素材。

### 首页

照 `../assets/报告模板与版式.md` 的首页规范做齐，三区加页底表：

1. **品牌横幅**：`assets/brand/zhifujie-logo.png`（1.4 cm）+ 深蓝「智富界」，同行右端「首次覆盖研究」+ 日期，下方亮蓝粗线
2. **标题区**：主标题（带判断）+ 副标题 + 公司全称/代码/行业归类
3. **双栏区**：左栏报告摘要（钩子设问领起 → 一/二/三 → 投资建议 → 风险提示，每层加粗判断领起，不写独立引言段，**要写满左栏版面**，投资建议层和风险提示层各带一句固定 AI 声明）；右栏十元素按固定顺序——**「AI 投资建议」区块标签**（8pt 加粗亮蓝 + 下方细线）→ 评级（首次）→ 目标价 → 当前价（带日期）→ 上行空间 →（浅灰细线分隔结论与市场数据）→ 总市值 → 日均成交（3 个月） → 相对表现图（阶段 4 窄版，**宽度取满右栏约 4.7 cm**）→ 亮蓝分隔线 → AI 研究团队块（「本报告由 AI 生成」+ 董AI/alex.dong@l2y.com + 李菲特/lester.li@l2y.com + 二维码 + 「扫码加入社群」）

首页页底**不放**盈利预测及估值摘要表——那张表在第 2 页。首页缺任一元素都不算完成。

### 第 2 页：Key data

四块内容全部收在一页，字号 7.5pt、单元格上下边距 30 DXA：

- **上半全宽**：公司盈利预测及估值摘要表（从阶段 2 模型 + 阶段 3 估值取数，含 A/E 年份标识），占满 18.6 cm
- **下半二列**（无边框表格，每栏 9.3 cm）：左栏放基本状况 + 现金流量表与资产负债表摘要，右栏放利润表摘要

这一页只放数据表，不写论述。全宽股价走势对比图放正文第一章，不放这里。

### 正文

正文不写独立引言段，直接从"一、公司概况"起（点题设问已并入首页摘要开头）。

**一、公司概况**——从阶段 1 的历史复盘、业务布局、财务分析整段取用，原文使用，不要重新摘要压缩。配阶段 4 对应图（沿革轴、股权图、分部收入、毛利率、财务趋势）。

**二、行业空间**——从阶段 1 的行业空间章取用素材。配市场规模图、产业链图、市占率图。多业务公司按分部讲空间。本章末尾从 Excel 的 `产业链主题` 摘取读者需要的精简产业链位置表和定价光谱，并写明产业链结论：目标公司位于哪个利润池、市场给哪些环节更高定价、关键变量如何传导到公司盈利和估值；完整池留在 Excel。

**三、核心驱动 / 竞争壁垒**——全文最重的一章。把阶段 1 的竞争格局、差异化优势，加上对投资逻辑最关键的变量（技术壁垒、生态、新业务、AI 等）展开论证，回答"凭什么是它、凭什么是现在"。从 Excel 的 `经营对标` 摘取关键经营对标，比较直接竞品的市占率、产品/客户/产能、收入增长、毛利率和关键经营指标；综合集团使用分部口径或明确标注集团口径污染。配经营对标图、竞争格局图，并写明经营对标结论：目标公司相对竞品的优势、短板、优势形成机制和对盈利预测的影响；完整视图留在 Excel。

**四、盈利预测与估值**——
- 4.1 盈利预测：从阶段 2 模型取用分部收入预测、利润预测、关键假设，把假设逻辑讲透（每条假设的驱动和依据，按产品/分部细分）。配分部预测图、三情景图、回测图。摘要财务表（收入/利润/毛利率/EPS，历史 + 预测）8–15 张。
- 4.2 估值：从阶段 3 取用相对估值、SOTP、DCF 辅证、目标价、评级、催化剂。从 Excel 的 `估值可比` 摘取支撑目标倍数的关键列和分位，完整的市值、收入、利润、PE、PS、分位和公式留在 Excel；只有可比公司进入目标倍数。配可比公司增长—估值图、SOTP 图、敏感性热力图、足球场图，并写明估值结论：相对可比组的溢价/折价、是否被增长/利润率/壁垒/周期解释、目标倍数的依据和会触发估值组迁移的变量。
- 4.3 风险提示：8–12 条，分类。

**附**（可选）：盈利预测三表摘要。

### 图表嵌入

阶段 4 的 40–70 张全部嵌入正文相应位置，不是附在文件夹里。O/V/T 完整表保留在 Excel；DOCX 需要展示的精简表必须生成为可编辑的原生 Word 表格，不得把 Excel 大表截图成 PNG。所有图片和原生表格按正文出现顺序统一分配「图表 N」，全文连续编号；阶段 4 的资产 ID 和建议顺序不等于最终编号。只保留页码内容目录，不另做图表目录（list of figures）。

O/V/T 三种视图共用阶段 3 Excel 的 `横向比较_主数据` 作为数字唯一权威来源：第二章只从 `产业链主题` 摘取产业链字段，第三章只从 `经营对标` 摘取经营字段，4.2 只从 `估值可比` 摘取估值字段。不要在三个章节重复粘贴同一张全字段大表，也不要在 DOCX 里重新抓取、重算或手录一套数字。

### 横向比较结论门

Word 交付前逐项确认三组结论均已进入正文，而不是只存在 Excel：

- 经营对标：经营强弱、优势机制、短板及对盈利预测的影响
- 可比公司估值：估值溢折价、目标倍数依据、重估/回落触发变量及对目标价/评级的影响
- 产业链：利润池位置、跨环节定价差异、传导变量及风险

三组结论落文时用上面这三个名字。O/V/T 是建池代号，正文、小标题、图注、表头和 Excel sheet 名一律不得出现，只保留在 `_data` 底稿。小标题写「小结：<结论>」，不写「O 池结论：<结论>」。

每组至少 1 条带数字或图表证据的明确判断。缺任一组，不得交付 Word。

**图和表一律占满宽度**：单张铺满 18.6 cm，成对的用无边框一行二列表格（`tblBorders` 全 none）各占 9.3 cm 并铺满该格。**缩小后孤零零居中在页面中间是禁止项**——那样左右各留一条无用空隙，是整份报告里最显廉价的地方。成对/可对照的图（分部增速对比、可比公司倍数、三情景、毛利率 vs 净利率等）优先拼一行；两张原生表格同样可以拼一行。注意双图并列要用阶段 4 生成的窄版（`figsize` 宽 3.66 in），别把全宽图硬缩到一半。

## 体量门槛

- 25–45 页 / 1.5–3 万字 / 40–70 图全嵌入 / 关键财务表 8–15 张
- 每页基本都有图或表，版面 60–80% 有内容
- 达不到说明没有充分展开，补充完善后再交付

## 不得简化

- 不写"本章节将包括……"，写实际内容
- 不写"此处插入图表……"，嵌入真实图表
- 不写"详见财务模型……"，把关键数提进正文
- 不为省篇幅压缩章节、跳小节
- 阶段 1 的公司概况内容原文使用，不重新缩写

## 跨文件一致性（交付前重点查）

研报里的数必须与 Excel 模型一致。抽 10–15 个公司核心数（营收、归母净利、EPS、各分部收入、目标价、评级）在 DOCX 和 Excel 间核对一遍；Excel 的四个横向 sheets 全量核对公司唯一键、层级、行情日、期间、币种、市值、收入、利润、PE、PS、关键经营指标和派生公式，DOCX 只核对实际展示的字段。首页右栏、首页页底摘要表、Key data 页、估值章、摘要里的目标价和评级要一致。预测年份口径全文统一（哪年 A、哪年 E）。

**口径一致性专项**（最易出错）：同一个指标全报告口径必须统一，不能这页用招股书口径、那页用年报口径。每个关键数就近标口径（招股书截止日 / 年报、绿鞋前 / 后、账面 / 经调整）。这些口径在前面各阶段的 `_data` 底稿里都记着，组装时照搬、别混。

**数据真实性是交付前阻断项**，和"渲染成 PDF 视觉核验"同级：

1. 跑 `scripts/anti_fabrication_lint.py`，把全部图表构建脚本、各阶段 `_data` 底稿、研报稿件传进去，命中逐条清除才算过。
2. 抽查正文和图表里的数，每个都能在 `_data` 底稿找到对应条目（数值、口径、时间点、来源对得上）；底稿里没有的数，补来源或删掉。
3. 高风险数（现价、市值、目标价、份额）的来源是不是一手结算源？验证有没有换异源、没用同源摘要或同盘中价 feed 互证？

这三条不过不交付。
