# 业绩更新研报（Earnings Update）

分析一家公司刚发布的业绩，给出这份业绩改变了什么。读者已经熟悉这家公司，不需要重述它是做什么的：报告的全部价值在新增信息：这一期比预期好还是差、差在哪、为什么、指引怎么变、原来的投资逻辑哪几条被强化或削弱、预测和目标价要不要改。

版式对标野村、摩根这类外资投行的机构研报并换成智富界自有标识，与 `initial-coverage-institutional`（下称首次覆盖版）共用同一套版式机制：logo 与「智富界」出现在每一页、蓝白配色、正文 12.7cm 窄栏而图表占满版心、图表与表格一律铺满宽度不孤立居中、首页右栏元素齐全且左侧有竖线。版式规范见 `references/Word文档格式标准.md` 和 `assets/报告模板与版式.md`，品牌资产在 `assets/brand/`。

**与首次覆盖版的分工**：首次覆盖回答「这家公司值不值得买」，25–45 页从零建立认知；业绩更新回答「这一期业绩改变了什么」，14–18 页只讲增量。公司尚未被覆盖过、没有可对照的旧预测时，不要用本 Skill 硬做，那说明缺的是首次覆盖，先说清楚再问用户。

整个流程拆成五个阶段，各自交付一个明确产物，后面三个阶段依赖前面的产出：

| 阶段 | 名称 | 前置 | 产物 |
|------|------|------|------|
| 1 | 业绩数据采集与超预期分析 | 公司名 / 代码 | 业绩速览稿 `[公司]_业绩速览_[日期].md` |
| 2 | 预测更新 | 阶段 1 | 预测更新表 `[公司]_预测更新_[日期].xlsx` |
| 3 | 估值与评级更新 | 阶段 2 | 估值稿 `.md` + 估值 sheet 并入阶段 2 的 Excel |
| 4 | 图表生成 | 阶段 1、2、3 | 图表包 `[公司]_图表_[日期].zip`（PNG + 清单） |
| 5 | 报告组装 | 阶段 1–4 全部 | 研报 `[公司]_[季度]_业绩更新_[日期].docx`；同时保留联动 Excel |

每个阶段的详细做法写在 `references/` 对应文件里，开始前先读那一份。涉及同业本期业绩对照时，同时读 `references/同业对照.md`。

`_data` 底稿、staging 和检查记录是取数、校验与追溯所需的内部工作文件，不改变上表的阶段交付物。它们保留到最终验收完成，除非用户要求，不作为独立交付件。

## Step 0：环境检查

任何完整流程或单阶段任务都先执行 Step 0，不因用户只要求某个阶段而跳过，也不自动安装或修复依赖：

1. 以本 `SKILL.md` 所在目录为基准运行 `python scripts/check_environment.py`。脚本会执行全部本地检查，不在首个失败处短路。
2. 退出码 0 表示本地检查全部通过；退出码 1 表示存在 `FAIL`，停止阶段 1–5，并把检查结果和「无法保证存在完整的运行环境」告知用户；退出码 2 表示只有 `REVIEW`，由 Agent 根据候选信息判断，无法确认时停止。
3. 本地检查通过后，由 Agent 确认当前环境具备联网搜索和页面获取能力。在 Claude Code 环境优先使用 `web_search` / `web_fetch`；其他环境使用等价工具。无法确认时停止并说明无法保证存在联网检索环境。
4. Step 0 全部通过后，才进入范围确认、前置校验和阶段 1–5。

## 怎么用

**用户要完整业绩更新**：先完成 Step 0，再回一句说明流程并从阶段 1 开始按序推进：

> 我来做 [公司] [报告期] 的业绩更新，分五步：业绩数据采集与超预期分析 → 预测更新 → 估值与评级更新 → 图表生成 → 报告组装。第一步先锁定最新一期的公告日和三口径对照。

不必等用户逐阶段催促。确认范围后连续推进，每个阶段产物落地、完成自检，再进入下一个。

**用户只要某一个阶段**：先完成 Step 0，再校验该阶段的前置是否齐备（见下）。前置缺失就停下，说清楚缺什么，不要拼凑占位内容。

**用户给了部分材料**（比如自己下载了财报 PDF、给了上一版模型或上一份研报）：读取后当作该阶段产物，跳过对应阶段，但仍要核对材料是否足以支撑后续阶段。上一版预测尤其重要：没有旧预测就没有「旧 vs 新」这一栏，报告的核心对照缺一半。

**没有旧预测怎么办**：如果这家公司此前没有被覆盖过、拿不到任何可对照的旧预测，先告诉用户，并给两个选项：① 用市场一致预期作为「旧」的替代基准，在报告里写明这一点；② 先走首次覆盖。不要自己编一个旧预测出来凑对照。

## 执行标准

这几条贯穿所有阶段，不达标不进入下一步。

**取数**。每个进研报的数字都要有来源、有日期，不依赖记忆中的旧数据。来源信任分三级，同一数据点取等级最高的：

1. 官方披露：业绩公告、季报年报、业绩会纪要、投资者演示材料、交易所披露平台（A 股巨潮资讯网、港交所披露易、SEC EDGAR）、公司投资者关系页
2. 用户放进工作目录的文件
3. 联网检索，在 Claude Code 环境优先使用 `web_search` / `web_fetch`；其他 Agent 环境使用自身可用的等价搜索与页面获取工具。Agent 根据当前运行环境和可用工具自行判断，不把这两个工具名视为跨环境硬依赖。用于获取一致预期、同业数据、第三方解读，并标清来源与日期

关键数据（本期收入、分部收入、归母净利、EPS、指引区间、一致预期）要两个独立来源互证，只有单一来源的标「单源」并降低置信度。多家媒体转引同一篇报道只算一个来源。训练数据会过时，时效敏感的数据一律当次检索。

下面六条取数要求同时适用于正文数字和图表数据点，不按数据所在位置降低核验标准。

**业绩公告日必须在今天前 3 个月内。** 这是业绩分析的第一大错误来源：拿了一个旧季度当成最新。开始前先写下今天日期，找到公告后读它自身的发布日期，亲自算一遍距今多少天。超过 3 个月说明拿错季度，回去重新检索，不要在旧数据上继续分析。检索时用「最新业绩」「最近季度」这类词，或直接进公司 IR 页按日期排序，不要按当前月份推断季度。业绩会纪要的日期必须与公告日期匹配（±1 天），对不上说明抓到了上一季度的纪要。

**一致预期必须取业绩公告前的快照。** 超预期/低于预期分析的分母是市场在公告前的预期，公告后一致预期已经被这份业绩改写，拿它来算差异等于用结果解释结果。取数时标明「截至 [公告前一交易日] 收盘」。取不到公告前一致预期时，在 `_data` 底稿标为未覆盖数据项，正文改用「vs 本报告此前预测」单口径对照并说明缺一致预期，不用公告后的数冒充。

**缺数不许编造。** 取不到的数据就留空或标「未获取」，绝不合成、插值、用「示意/近似」填一个看起来合理的值。「约/近似/示意」只能标真实数据的精度（四舍五入、估算区间），不得用来标一个根本不存在的数。图表缺数同理，宁可少画一根柱、少画一条线，也不补造。公司未给指引时明确写「本期未给出指引」，不要替它推一个。

**每个数先进 `_data` 底稿。** 底稿五字段：`数值 | 口径 | 时间点 | 来源（含链接）| 置信度（高/中/低 + 单源/双源）`。正文和图表里每一个数，都要能在底稿找到对应条目：**底稿里没有的数，不许落进正文或图表**。底稿开头另起一节「数据源盘点」，写清本次检查过哪些数据源、哪些可用、哪些不可用或覆盖不足、哪些数据项没有授权源覆盖、降级到了什么路径。这一节的摘要要进报告的「来源与参考资料」。

**时效市场数据回结算一手源。** 股价、指数、市值、成交这类时效极强的数，必须取交易所或行情接口的**结算日线收盘**，明确区分盘中价和收盘价，原始序列落盘到底稿。搜索摘要、英文实时 feed 只作线索、不作终值。业绩更新有一个特殊要求：**公告前一日收盘价和公告后首个交易日收盘价都要取到**，因为市场反应本身是报告要解释的对象。示例接口按市场选（A 股：东方财富 push2his、新浪；港股：东方财富 push2his `secid=116.<code>`、富途；美股：交易所/SEC 及主流行情接口），是示例不是唯一。**只要画股价图，价格一律取日频逐日收盘**，不周频重采样、不插值凑点。

**验证要独立于原值的信源。** 核验一个数时，换一类信源重新得出，优先回一手结算源；不许用与原值同源、同链的摘要互证。「多家媒体转引同一篇只算一个来源」扩展到「多个实时 feed 报同一盘中价，也只算一个口径」。业绩数字优先回公司公告原文或财报表格，不用媒体转述的整数。

**市场自适应**。不预设市场。先确认标的在哪个市场挂牌：A 股看中国会计准则、人民币、单季与累计口径的区分；港股美股按当地准则和币种。**财年口径要专门核**：财年截止非 12 月的公司（Apple 9 月、Nike 5 月、Walmart 1 月），「Q3」指的期间与自然年完全不同，报告里必须写清报告期对应的自然月份区间。单季与累计（A 股三季报是累计口径）不得混用，用哪个口径就全篇用哪个，并在表下注明。

**同业对照（可选）**。同业本期已披露业绩时，做一张横向对照：同期收入增速、利润率、超预期幅度、指引变化。规则见 `references/同业对照.md`。这一节是可选的：同业尚未披露时直接跳过并说明，**不得用旧季度数据凑一张表**。业绩更新不建首次覆盖版那套三层标的池，不做分位统计，不用同业倍数重定目标倍数。

**输出规范**。最终交付 DOCX，必须符合 `references/Word文档格式标准.md`：机构标识、配色、字体、字号、行距、页边距、首页双栏、正文窄栏、表格、图注、页眉页脚、禁止项、15 步交付前核验（含 `check_render.py` 渲染门）都按那份执行，这是硬要求。业绩更新特有的信息编排（首页三区、业绩速览页、章节逻辑）见 `assets/报告模板与版式.md`。两份一起遵守，正文字体字号行距标题颜色以格式标准为准。

**机构标识不可省略**。logo 和「智富界」必须出现在每一页（首页在顶部品牌横幅，其余页在页眉右上角），首页右栏元素按固定顺序齐全，右栏左侧有贯穿的深蓝竖线。摘要写长了就压缩摘要，不得挤掉右栏元素或省掉品牌标识。品牌资产用 `assets/brand/` 下的相对路径，不引工作区外的绝对路径。

**写作**。所有文字（研报正文、各阶段稿件，以及本 Skill 自己的产出说明）都按 `assets/研报写作规范.md` 来写，拿不准的句子查 `assets/去AI味案例库.md`。这一条不是可选项，是底线。

下面三条是最容易犯、也最伤专业度的，写的时候就避开，不是写完再改：

**先给结论，第一句就说超预期还是低于预期。** 业绩更新的读者只有一个问题：这期比预期好还是差、差多少。摘要第一句、正文第一章第一句、每个要点的加粗领起句，都要直接给判断加数字，不要用「本季度业绩呈现出一些值得关注的变化」这类什么都没说的开场。

**只写结论，不写研究过程。** 研报正文给的是判断和依据，不是工作日志。这五类一律不进正文：① 样本与取数过程（「一致预期取自四家机构」「数据取自 XXX」「筛选后保留三家」）；② 困难叙述（「问题是……」「跨度太大」「不具备参考意义」「只能取……」「因此只好……」）；③ 自指（「全篇最关键的假设」「这条分界线值得单独标出来」「接下来要回答的是……」「拆开看」）；④ 自辩（「这不是额外的悲观假设」「并非刻意保守」）；⑤ 第一人称。样本范围体现在结论本身，数据来源写在图表下方小字、`_data` 底稿和「来源与参考资料」章节里。

分组段落：比如「哪些分部的表现有解释力、哪些没有」：直接给两组判断：谁有、凭什么（带数字）；谁没有、凭什么（带数字）。小标题同样给结论，不写「遇到什么困难 + 怎么绕过去」。

**全文禁用第一人称。** 不出现「我们」，改成无主语或「本报告」：「我们把 FY2026E 收入从 4,791 亿上调到 4,930 亿」写成「FY2026E 收入从 4,791 亿上调到 4,930 亿」。旧预测的归属写「本报告此前预测」，不写「我们此前预测」。交付前从 `document.xml` 抽纯文本 grep 断言全文 0 处「我们」，不靠肉眼扫。

边界：分析性判断（「不认为指引隐含的下半年斜率能兑现」「若需求不及预期」）和假设本身（「假设 4QFY2026E 增长 4.0%」）照常写，被禁的是对自己工作流程的叙述。

**工作代号不进交付物。** `_data` 底稿和 Excel 里为了处理方便会用一些短代号：beat/miss 标记列、样本编号、`seg_A`/`seg_B` 这类分部占位、staging 的批次号。读者不知道它们指什么。这些只允许留在底稿；DOCX 正文、章节标题、图表标题、图注、表头、表内取值，以及 Excel 的 sheet 名和单元格文字，一律换成读者能读懂的说法：`beat` → 「高于预期」、`miss` → 「低于预期」、`seg_A` → 分部真实名称。Excel 同样是交付物。交付前跑 `scripts/checks/check_internal_labels.py` 断言 0 命中。

**术语**。DCF、WACC、EV/EBITDA、PEG、ROE、FCF、Capex、ARPU、YoY、QoQ、bps、GAAP / non-GAAP 这类专业缩写和股票代码原样保留，不强行翻译。年份标记用 A 和 E：已实现的期间写 `3QFY2026A`，预测期间写 `4QFY2026E`，全篇一致。

## 进入正式产出前

每个阶段动手写正式产物之前，先做两件事：

1. 读规范：`assets/研报写作规范.md`、`assets/报告模板与版式.md`（涉及 Excel 或 DOCX 时）、`assets/质量检查清单.md`；产出 DOCX 时还要读 `references/Word文档格式标准.md`。
2. 做一次数据来源盘点，这一阶段需要哪些数据，哪些已获取（标来源和日期），哪些尚未获取。未获取的数据要么继续检索，要么在产物里明确标「未获取」并说明用什么假设替代、依据是什么。不要因为缺数据就跳过章节或编造数据填入。

## 前置校验

阶段二到五开始前必须核对前置。缺失就停，列出缺口，问用户是否先补，不要造占位内容。

- 阶段 1：无前置，但要能确认标的最近一期业绩已发布且公告日在 3 个月内
- 阶段 2：阶段 1 的业绩速览稿在，且含本期实际值、三口径对照、可对照的旧预测（或已确认用一致预期替代旧预测的基准）
- 阶段 3：阶段 2 的预测更新表在，且含旧/新预测与变动原因
- 阶段 4：阶段 1、2、3 产物齐，且外部行情数据（12 个月日频收盘、公告前后收盘）能获取
- 阶段 5：阶段 1、2、3、4 产物全部齐，且各自达到规定的体量与质量

举例，用户说「用这个 Skill 给某公司直接出阶段 5 报告」，而前四个阶段产物都不在：

> 阶段 5 要先有前四个阶段的产物。现在业绩速览稿、预测更新表、估值稿、图表包都还没有。要我从阶段 1 开始按序做完，还是你已经有部分产物可以提供？

## 只交付指定产物

每个阶段只交付上表列出的产物。不要额外生成「完成总结」「执行摘要」「下一步说明」「任务清单」等未要求的文档。阶段产物之外的进展、来源、缺口和待决策项在对话中说明。

内部工作文件不计入额外交付物：`_data` 底稿、staging 和检查记录按执行标准生成并保留用于追溯与验收，但不需要作为单独成果向用户展示或交付，除非用户明确要求。

## 不走捷径

这是机构级业绩更新报告，体量和密度是硬指标（见 `assets/质量检查清单.md`）。不得用以下方式简化敷衍：

- 写「本章节将包括……」占位，而不写实际内容
- 标「此处插入图表……」，而不真的生成并嵌图
- 写「详见财务模型……」，而不把关键数据提进正文
- 只写超预期幅度，不解释差异从哪来
- 只给新预测，不给旧预测和变动原因
- 为省篇幅压缩章节、跳过小节
- 只做 8 张图就结束（业绩更新要 18–25 张）

业绩更新比首次覆盖短，但短的是覆盖范围不是分析密度。省掉的是公司背景介绍，不是差异归因和逻辑重估。

图表数量不得优先于数据真实性。不得用编造、示意或插值数据达到体量要求。真实数据只能支持 15 张图时，交付 15 张并说明未达 18 张的原因。某张必备图的数据不足时，只画已知值，或省略并注明原因。

## 验收

最终报告交付前，对照 `assets/质量检查清单.md` 逐项核对：体量达标、图表数量和质量达标、跨文件数字一致（研报里的数与 Excel 一致）、来源齐全、结构是业绩更新的逻辑链、写作无 AI 味。任何一项不达标，补充完善后再交付。

数据真实性是**和渲染级 QA 同级的交付前阻断项**，不是软标准：

1. 跑 `scripts/anti_fabrication_lint.py`（传图表构建脚本、各阶段 `_data` 底稿、稿件路径），命中要逐条清除，指到 `_data` 真实来源，或删掉该数据/系列；清不掉不交付。脚本只兜机械可检的编造痕迹，看起来合理的错数还得靠下一条。
2. 抽查正文和图表里的数，每个都能在 `_data` 底稿找到对应条目（数值、口径、时间点、来源对得上）。底稿里没有的数，回去补来源或删掉。

这两条不过，不交付：和「DOCX 必须渲染成 PDF 做视觉核验」是同一级别的硬门。
